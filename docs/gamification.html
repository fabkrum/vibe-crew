Progression & Rewards

Gamification System

VibeCrew includes a persistent progression layer that motivates across sessions and teaches vibe-coding skills over time. It tracks your growth from your first /setup through hundreds of shipped features.

⚖
Artifacts over actions

Rewards map to real outputs — shipped features, passing tests, clean sessions — not arbitrary clicks.

★
Teaching over tracking

Every mechanic helps you improve. Challenges target your weakest skills. Quizzes explain the answer.

♥
Sustainable over addictive

Grace periods for streaks, opt-in challenges, no toxic leaderboards. Taking time off is never punished.

How it runs

The gamification pipeline runs automatically at the end of every /wrap. Six scripts execute sequentially: award XP, check level-up, update streak, distribute skill XP, check badges, and update challenges. You never need to run anything manually.

Configuration

Enabling & Disabling

There are two ways to control gamification, and they stay in sync automatically.

Option 1: User Profile (recommended)

Run /profile and answer the gamification question. This sets the gamification_preference dimension, and VibeCrew automatically syncs the corresponding config flags.

Profile SettingWhat You SeeConfig Flags
All In (full) XP, badges, streaks, challenges, level-ups, streak reminders, quizzes — everything enabled: true, show_xp: true, streak_reminders: true
Light Touch (light) XP and badges display, but no streak reminders — low-key progression enabled: true, show_xp: true, streak_reminders: false
Score Only (score_only) Vibe Score only. No XP, no badges, no streaks display. Progression still tracked silently enabled: true, show_xp: false, streak_reminders: false
Disabled (disabled) All gamification output suppressed. Vibe Score and Performance Coach still operate independently enabled: false, show_xp: false, streak_reminders: false

Option 2: Direct config edit

Edit .vibecrew/config.json directly. The gamification block controls everything:

Full gamification (all features on)

"gamification": {
  "enabled": true,
  "streak_reminders": true,
  "quiz_frequency": "weekly",
  "show_xp_in_status": true
}

Gamification disabled

"gamification": {
  "enabled": false,
  "streak_reminders": false,
  "quiz_frequency": "weekly",
  "show_xp_in_status": false
}
What happens when disabled?

All gamification scripts check config.json on entry. When enabled is false, every script exits immediately with no output and no file modifications. Your gamification.json data is preserved — nothing is deleted. Re-enable at any time and pick up where you left off.

Vibe Score is independent

Disabling gamification does not disable the Vibe Score. The score measures session quality and feeds the Performance Coach — it operates as a core system, not a gamification feature. You always get your score at /wrap.

Session Quality

Vibe Score

Every session ends with a quality score (0–130+). It starts at 100 and adjusts based on real work artifacts. The score is the single data source for XP, badges, challenges, and Performance Coach analysis.

Deductions

Points are removed for anti-patterns detected during the session:

Anti-PatternDeductionWhat It Means
Prompt churn−5 per sequenceRephrasing the same instruction multiple times without progress
Tool loops−10 per loopRetrying the same failed command with the same approach
Low cache utilization−15Cache ratio below 50% (inefficient token usage)
Context violations−20Peak context usage exceeded 60% of the window
No tests−10Test files exist but zero tests pass
No feature spec−5Active feature missing acceptance criteria
Skipped code review−5Review phase not completed for the feature
Documentation drift−3 per stale docSource code changed but matching feature docs not updated
Console errors−5Console errors detected on affected pages
Visual token violations−3 each (max −9)Design system token violations (hardcoded colors, wrong spacing, etc.)
Plan revisions ≥ 2−5Plan or spec revised 2+ times mid-feature (insufficient upfront planning)
Phase artifact expectations

Expected artifacts per phase: Plan → docs/features/{name}/plan.md, Design → design.md, Code → source files, Test → test files, Docs → feature documentation. Trivial features skip Design and Review, so missing design.md or review reports are not penalized for trivial complexity.

Bonuses

Points are awarded for best practices:

Best PracticeBonusCondition
Complete phase artifacts+30 maxAll Tier 2 phases (Plan, UI, Code, Test, Review, Docs) completed
High cache utilization+10Cache ratio above 70%
Full test coverage+15Coverage above 80%
Clean session+5Zero deductions
TDD discipline+3Tests written before implementation code
E2E tests passing+3Playwright/E2E suite passes
Accessibility clean+2No critical or serious a11y issues
Code review complete+2Review phase completed for the feature
Performance baselines+2Performance metrics tracked
Visual compliance clean+3Design system tokens used correctly throughout
A perfect session

A session with zero deductions and all bonuses can score 130+. This is rare but achievable — it means you planned thoroughly, wrote tests first, hit high cache, shipped with docs, and kept the context window lean.

Consistency

Streaks

Streaks track consecutive days of coding. They’re designed to celebrate consistency without demanding it — a broken streak is just a number, not a loss.

How they work

📅
Increments on /wrap

Each calendar day you run /wrap counts. Multiple wraps per day still count as one.

🌞
Weekend auto-grace

Saturdays and Sundays never break streaks and never consume grace credits. Take weekends off freely.

❄
2 grace days per month

Miss a weekday? The streak continues if you have grace days remaining. Resets on the 1st of each month.

💚
No penalty for breaking

When a streak breaks, the counter resets to 0. No XP is lost, no badges are revoked. Start fresh.

🔔
Reminders are opt-in

Streak reminders are disabled by default. Enable via /profile (set gamification to “All In”) or in config.json.

Streak data tracked

streak.currentCurrent consecutive day count
streak.longestAll-time longest streak (for bragging rights)
streak.last_session_dateLast date /wrap was run
streak.grace_days_remainingGrace credits left this month (0–2)
streak.frozen_todayWhether a grace day was used today

How quizzes are triggered

  1. Explicit: Run /quiz for a random quiz, or /quiz context-management-101 for a specific one
  2. Contextual: The Performance Coach suggests a relevant quiz after /wrap when it detects an anti-pattern (e.g., low cache → context-management-101)
  3. Periodic: Session Startup suggests an overdue quiz if more than 30 days since the last one (never forces it)

XP from quizzes

+5 XP per correct answer, awarded only on first completion. You can retake quizzes for practice but won’t earn XP again. Quiz XP is intentionally modest — it cannot substitute for real work XP.

Self-Improvement

Performance Coach

The Performance Coach is an Opus agent that analyzes Vibe Score trends across sessions and proposes permanent improvements to your project’s CLAUDE.md. It’s the self-improving feedback loop at the heart of VibeCrew.

How it works

1
Detection

Reads the latest score file, extracts deduction patterns

2
Correlation

Cross-references against MEMORY.md to find recurring patterns

3
Eligibility

Validates against guardrails: min 5 sessions, no duplicates, not recently rejected

4
Proposal

Generates a specific CLAUDE.md rule mutation targeting the highest-impact pattern

5
Decision

You approve, reject, or edit the mutation. Rejections have a cooldown period

6
Recording

Updates MEMORY.md and mutation-log.json for future analysis

Guardrails

  • Max 1 mutation per session — prevents overwhelming changes
  • Min 5 sessions required before any mutation is proposed
  • 3-rejection cooldown: rejected patterns wait rejection_count × 7 days before being proposed again
  • No duplicate rules — won’t propose what already exists in CLAUDE.md
  • No hook-redundant rules — won’t propose rules that hooks already enforce
  • Max 15 Session Learnings in CLAUDE.md — auto-prunes oldest entries

Pattern templates

The coach tracks six anti-pattern categories and generates targeted mutation proposals:

PatternScore ImpactExample Mutation
Prompt Churn−5 per sequence“Write acceptance criteria before starting implementation”
Tool Loops−10 per loop“After 2 failed attempts, change approach instead of retrying”
Low Cache−15“Use Context7 for library docs instead of pasting them”
Context Violations−20“Offload research to worktree subagents”
Missing Artifacts−5“Always run /check before /wrap”
Documentation Drift−3 per doc“Update feature docs in the same session as code changes”

Technical Details

Data Files & Storage

All gamification state is stored locally in your project’s .vibecrew/ directory. Nothing leaves your machine.

FilePurposeUpdated By
.vibecrew/gamification.jsonLevel, XP, badges, skills, streaks, challenges, quiz progress, statsaward-xp.sh, check-badges.sh, update-streak.sh, etc.
.vibecrew/config.jsonGamification toggle, streak reminders, quiz frequency, user profile/profile, manual edit
.vibecrew/scores/score-*.jsonPer-session Vibe Score breakdown (deductions, metrics, phases)calculate-vibe-score.sh
MEMORY.mdPerformance Coach persistent memory (anti-patterns, mutations, trends)Performance Coach agent
.vibecrew/mutation-log.jsonHistory of proposed, accepted, and rejected CLAUDE.md mutationsapply-mutation.sh

Concurrency safety

All gamification scripts use advisory locks (.vibecrew/locks/gamification.lock) and atomic writes (temp file + mv) to prevent corruption when multiple agents update simultaneously.

Data portability

Your gamification.json file is self-contained. If you move to a new machine, copy .vibecrew/gamification.json and .vibecrew/config.json to preserve your full progression history.

Templates

Templates are the scaffolding blueprints VibeCrew uses to create consistent, well-structured artifacts across every project. From the initial VISION.md to test configs and session logs, every file that VibeCrew generates starts from a template. This ensures consistency, reduces agent token cost (no need to invent formats from scratch), and makes outputs predictable.

■
What they are

50+ template files in the templates/ directory: Markdown documents, JSON schemas, test configs, CI/CD pipelines, and a full VitePress documentation site scaffold. Agents fill in project-specific content while the structure stays consistent.

✓
What problem they solve

Without templates, agents would invent different file formats each session — inconsistent backlog schemas, varying session log structures, and unpredictable CLAUDE.md layouts. Templates guarantee that every artifact works with every script, hook, and dashboard component.

Tier 1 Foundation Templates

These templates drive the /new-project workflow. Each foundation step produces a file from its template, filled with project-specific content by the responsible agent.

TemplateOutputCreated ByWhat It Defines
VISION.md.template VISION.md Orchestrator Product vision, target audience, core value proposition, success metrics, and project scope.
design-system.css.template design-system.css Design Discovery or Import CSS custom properties: colors, typography, spacing, radius, shadows, breakpoints — the design token file.
design-brief.md.template design-brief.md Design Discovery or Import Rationale for design decisions — why these colors, fonts, and styles. Agents reference this during feature development.
tdr.md.template TDR.md Stack Scout Technology Decision Record: framework, database, auth, hosting, testing, CI, with Token Impact Assessment for each choice.
roadmap.md.template ROADMAP.md Orchestrator Feature roadmap with priority phases, dependencies, and estimated complexity.
CLAUDE.md.template CLAUDE.md Orchestrator Project-level AI rules: conventions, constraints, architecture patterns, and session learnings. Kept under 200 lines.

State & Config Templates

Created during /setup to initialize the .vibecrew/ runtime directory. These define the JSON schemas that scripts, hooks, and the dashboard all rely on.

TemplateOutputWhat It Defines
config.json.template .vibecrew/config.json Terminal preference, notifications, user profile dimensions, cost thresholds, MCP server toggles.
state.json.template .vibecrew/state.json Foundation completion flags, active feature, current phase, feature history.
backlog.json.template .vibecrew/backlog.json Feature specs with Kanban columns, priority, complexity, acceptance criteria, and dependencies.
gamification.json.template .vibecrew/gamification.json XP, level, badge definitions, skill tree, streak tracking, challenge completions.

Testing & Quality Templates

Scaffolded into the project when the corresponding testing command is first used. Each template follows best practices for its test framework.

TemplateOutputWhat It Configures
vitest.config.ts.template vitest.config.ts Unit testing with Vitest: coverage thresholds, test environment, setup files.
playwright.config.ts.template playwright.config.ts E2E testing with Playwright: browsers, base URL, screenshot/video settings.
axe-config.ts.template axe.config.ts Accessibility testing with axe-core: WCAG 2.1 AA rules, element selectors.
k6-config.js.template k6.config.js Performance testing with k6: load, stress, spike, and soak test scenarios.
test-utils.ts.template test-utils.ts Shared test utilities: render helpers, mock factories, custom matchers.

Reporting Templates

Structured JSON schemas for every type of report VibeCrew generates. These ensure consistent machine-readable output that the dashboard and scripts can parse.

TemplateGenerated ByWhat It Captures
session-log.json.template/wrapSession timestamps, features worked on, Vibe Score, token usage, estimated cost.
score-breakdown.json.template/wrapDetailed Vibe Score: each deduction and bonus with reasons and line items.
handoff.md.template/handoffStructured context transfer: current state, pending work, blockers, next steps.
audit-report.json.template/auditOWASP findings: vulnerability type, severity, file location, remediation.
ci-heal-report.json.template/healCI failure diagnosis: category, each fix attempt, outcome.
simplification-report.json.template/simplifyDead code, over-abstractions, API surface bloat with before/after diffs.
mutation-proposal.json.templatePerformance CoachCLAUDE.md rule proposals: anti-pattern detected, proposed rule, evidence.

Reference Data

Static data files that agents and scripts reference but don't modify per-project.

FileWhat It Contains
mcp-registry.json25 MCP server definitions with trigger patterns, commands, env vars, and docs links. Powers TDR-based auto-discovery.
badge-catalog.jsonAchievement badge definitions: names, unlock conditions, XP rewards, icons.
challenge-pool.jsonGamification challenges: daily, weekly, and milestone challenges with reward criteria.
signal-schema.jsonInter-agent signal file validation schema. Hooks validate signals against this before writes.
architecture-diagrams/5 Mermaid diagram templates (.mmd) for system topology, ER schema, state flows, API sequences, and component tree.

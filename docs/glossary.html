Glossary

Key terms and concepts used throughout VibeCrew. Click a letter to jump to that section.

ABCDFGHIMOPQRSTVW

A

Agent Agents
A specialized AI team member that handles one specific job. VibeCrew has 14 agents — think of them like departments in a company. One writes code, another reviews it, another handles documentation, and so on. Each agent is tuned for its role, so the right expert always handles the right task.
Anthropic: Agentic tool use →

B

Backlog Workflow & Process
Your project’s to-do list, stored as a file (.vibecrew/backlog.json). It contains every feature you want to build, ranked by priority. Each item includes a name, a short description of what it does, how complex it is, and whether it’s been started yet. The /run-backlog command works through this list automatically.
Builder Agents
The agent that actually writes your application code. When it’s time to turn a plan into working software, the Builder takes the feature specification and implements it — creating files, writing functions, and connecting components. It works in an isolated copy of your project so that its work doesn’t interfere with your main codebase until it’s ready.

C

CLAUDE.md Tools & Infrastructure
A special instruction file at the root of your project that Claude reads every time a session starts. Think of it as a “house rules” document — it tells Claude about your project’s conventions, patterns, and hard-won lessons from previous sessions. VibeCrew keeps it under 200 lines so it stays fast to read.
Anthropic: Claude Code memory →
Code Auditor Agents
An agent that examines an existing codebase to understand how it works. When you bring an existing project to VibeCrew (via /onboard), the Code Auditor reads through your code, identifies the patterns and conventions already in use, and creates a CLAUDE.md file so future sessions respect your project’s established style.
Code Reviewer Agents
An agent that reads through newly written code and checks it for problems — like having a colleague review your work before it ships. It verifies the code matches the feature specification, follows the technology choices in the TDR, and respects the project’s coding conventions. Triggered by the /review command.
Code Simplifier Agents
An agent that finds ways to make your code leaner. It looks for unused code that can be deleted, over-complicated abstractions that can be flattened, and places where the same thing is done in different ways. Think of it as a professional organizer for your codebase. Triggered by /simplify.
Context Window Tools & Infrastructure
The amount of information the AI can “hold in its head” during a single conversation. Just like a person can only think about so many things at once, the AI has a limit on how much text it can process. VibeCrew carefully manages this — targeting less than 50% usage and showing warnings at 60% and 80% to prevent slowdowns.
Anthropic: Context windows →

D

Design Discovery Design & Quality
A guided conversation that happens early in your project to figure out how your app should look and feel. It asks questions in three rounds: first about your product and audience, then about visual style preferences, and finally about specific component choices. The result is a design system file and a brief that all agents reference when building your UI.
Design System Design & Quality
A single CSS file (design-system.css) that defines your project’s visual language — colors, fonts, spacing, button styles, and more. Created during Tier 1 based on your Design Discovery answers. Every component the Builder creates uses these shared values, ensuring your whole app looks consistent without manual styling.
Doc Generator Agents
The agent responsible for keeping your project’s documentation up to date. After features are built, it writes session summaries, updates the changelog, creates feature documentation, and prepares release notes. It runs during the /wrap command to make sure documentation never falls behind the code.

F

Feature Cycle Workflow & Process
The six-step process every feature goes through: Plan (decide what to build) → UI Design (sketch the interface) → Code (write the software) → Test (verify it works) → Review (check for quality) → Docs (document it). This cycle repeats for each feature, ensuring nothing is shipped half-baked.
Foundation Workflow & Process
The collection of planning documents created before any code is written. Includes the project vision, design system, technology decisions, architecture diagrams, feature roadmap, and CLAUDE.md. Think of it as the blueprint phase — you wouldn’t start building a house without plans, and VibeCrew won’t let you start coding without a foundation.

G

Gamification Design & Quality
An optional feature that turns your development sessions into a game-like experience. You earn XP for completing tasks, unlock badges for milestones, build skill trees, and maintain streaks for consistent work. It’s entirely optional — you can turn it on, use a lighter version, or disable it completely via the /profile command.

H

Handoff Workflow & Process
A summary document generated by the /handoff command when you need to continue work in a new session. It captures what was done, what’s in progress, and what comes next — like leaving detailed notes for yourself (or a colleague) to pick up exactly where you left off without losing context.
Hook Tools & Infrastructure
An automatic safety check that runs behind the scenes at specific moments — like when you start a session, save a file, or finish a task. Hooks enforce rules without the AI needing to remember them, which makes them faster and more reliable. For example, a hook prevents you from writing code before the project foundation is ready.
Anthropic: Claude Code hooks →

I

Inline Agent Agents
An agent that works directly inside your main conversation, sharing the same context window. This is efficient for quick tasks (like running checks or routing decisions) but means its work counts against your session’s memory limit. Compare with a Worktree Agent, which works in its own separate space.

M

MCP Tools & Infrastructure
Short for Model Context Protocol — a standard way for AI to connect to external tools and services. Think of it like USB for AI: a universal plug that lets Claude talk to databases, testing tools, documentation libraries, and more. VibeCrew ships with 9 MCP connections pre-configured.
Model Context Protocol →
MCP Server Tools & Infrastructure
A service that gives Claude access to a specific tool through MCP. Each server adds a capability — for example, Context7 provides access to library documentation, Playwright lets Claude test web pages, and Supabase connects to your database. You can think of each server as a specialist tool in Claude’s toolbox.
MCP: Example servers →

O

Opponent Processor Agents
An agent that plays devil’s advocate. After technology decisions are made, the Opponent Processor deliberately challenges them — looking for risks, blind spots, and alternatives that might have been overlooked. It produces a structured debate showing pros and cons for each choice. Triggered by /reconsider.

P

Performance Coach Agents
An agent that watches how your sessions go and suggests improvements. It looks for patterns like repeated mistakes, wasted effort, or missed best practices. When it spots a recurring issue, it can propose adding a new rule to your CLAUDE.md — making the system permanently smarter based on real experience.
Phase Gate Workflow & Process
A built-in checkpoint that blocks certain actions until prerequisites are met. The most important one prevents any application code from being written until the Tier 1 foundation is complete. This ensures you always have a solid plan before coding begins — it’s like a construction permit that won’t be issued until blueprints are approved.
Profile Tools & Infrastructure
Your personal preferences, stored in the project config. It covers eight areas: your technical role, coding experience, how much you want to oversee, PR review style, how detailed you want explanations, gamification preference, learning mode, and risk tolerance. Every agent reads your profile and adapts its behavior — a founder gets different explanations than a senior developer.

Q

Quality Gate Workflow & Process
An automatic check that runs every time a task finishes. It scans your modified files for type errors, linting issues, and build failures. If something is broken, it catches it immediately rather than letting problems pile up. Think of it as an automatic quality inspector at the end of every assembly line step.

R

Roadmap Workflow & Process
The initial plan of features to build, created during Tier 1. Typically 5–8 features ranked by how much value they deliver to users. The roadmap becomes the starting point for your backlog and gives the whole project a clear direction from day one.

S

Session Learning Tools & Infrastructure
A lesson learned from a development session that gets permanently added to your CLAUDE.md. For example, if the Performance Coach notices you keep running into the same issue, it proposes a rule to prevent it in future sessions. The system keeps a maximum of 15 learnings and automatically removes the oldest ones to stay concise.
Stack Scout Agents
The research agent that evaluates technology options for your project. Before any code is written, Stack Scout searches the web, reads library documentation, and compares alternatives to recommend the best tools for your specific needs. It produces a Technology Decision Record (TDR) explaining what was chosen and why.

T

TDR Tools & Infrastructure
Short for Technology Decision Record — a document that lists every major technology choice for your project and the reasoning behind it. Framework, database, hosting, authentication — each decision is recorded with alternatives that were considered. This prevents second-guessing later and keeps all agents aligned on the same tech stack.
Tier 1 Workflow & Process
The first phase of any VibeCrew project: planning before coding. It’s a one-time, step-by-step process that creates your project vision, design system, technology decisions, architecture diagrams, and feature roadmap. No application code can be written until Tier 1 is complete. Think of it as the architect phase before construction begins.
Tier 2 Workflow & Process
The second phase: building features. After the Tier 1 foundation is set, Tier 2 runs the Feature Cycle repeatedly — one feature at a time, each going through Plan → UI Design → Code → Test → Review → Docs. This is the phase where your application actually gets built, feature by feature.

V

Vibe Dashboard Tools & Infrastructure
A web page you can open in your browser to see your project’s status at a glance. It shows a Kanban board of features (planned, in progress, done), session statistics, Vibe Score trends over time, test coverage, and any achievements you’ve earned. It’s a visual control center for your project.
Vibe Score Design & Quality
A quality rating for each development session, scored from 0 to 130. It measures things like how efficient your prompts were, whether tests were written, if documentation is current, and whether the workflow was followed properly. A high score means the session was clean and productive; deductions highlight areas to improve.
VISION.md Tools & Infrastructure
The first document created in any VibeCrew project. It captures what you’re building, who it’s for, and what success looks like. Every agent references this document to make sure decisions align with the project’s purpose. Think of it as your project’s north star.

W

Worktree Agent Agents
An agent that works in a completely separate copy of your project, with its own memory space. When VibeCrew needs to do heavy research, review code, or evaluate options, it sends a Worktree Agent so that work happens in isolation. This keeps your main session fast and focused — like sending a colleague to a library to do research while you keep working at your desk.
WIP Limit Workflow & Process
Short for Work-In-Progress Limit — a rule that prevents more than 2 features from being actively worked on at the same time. This prevents spreading too thin and ensures each feature gets the attention it needs to be completed properly before starting the next one.

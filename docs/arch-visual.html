How VibeCrew Works

VibeCrew is a system of interlocking parts: a plugin shell, specialized agents, lifecycle hooks, slash commands, bash scripts, and per-project runtime state. Select a tab to see how each part fits together.

Plugin Structure

VibeCrew is a Claude Code plugin — an add-on that gives Claude Code new abilities. When you open a project with VibeCrew installed, Claude Code reads a manifest file and automatically loads agents, skills, hooks, scripts, MCP servers, and permissions. Everything lives inside the claude-plugin-vibe-crew/ directory.

■
What it is

A self-contained folder with a plugin.json manifest that registers agents, slash commands, hooks, scripts, and MCP servers — everything the system needs in one install.

✓
What problem it solves

Without a plugin, you'd manually configure each agent, permission rule, and automation script for every project. The plugin bundles everything into a single install.

Plugin Components

Skills skills/ Slash command definitions as SKILL.md files. Each contains YAML metadata and a workflow body that routes to the right agent(s).
Templates templates/ Project scaffolding templates, doc-site scaffold, and an MCP registry of additional servers that can be auto-discovered from TDR technology choices.
Tests tests/ BATS test suite that validates hook scripts, state management, and core plugin behavior.

Plugin components and how Claude Code loads them

Sub-Agents

Instead of one AI doing everything, VibeCrew splits work across specialized agents — like a real development team with planners, builders, testers, and reviewers. Most agents run on Opus, the most powerful model available. This is intentional: while Opus costs more per task and takes longer, the higher quality output means significantly less rework. Getting it right the first time saves more time and money than running a cheaper model that needs multiple correction rounds. Fast, mechanical tasks (routing, running shell commands) use Haiku, and template-driven output like documentation uses Sonnet.

■
What they are

AI specialists with scoped tool access, model selection, and turn budgets. Most run on Opus (the most capable model) because planning, coding, security, and analysis are tasks where mistakes are expensive to fix later. Haiku handles fast mechanical work, and Sonnet handles documentation.

✓
What problem they solve

A single AI context window fills up fast when researching, coding, and testing in one session. Worktree agents offload expensive research into isolated contexts — only the distilled output enters your main session, saving thousands of tokens.

Agent topology: how agents hand off work to each other

Hooks

Hooks are automatic safety checks that run behind the scenes at zero token cost. When an agent tries to write a file or run a command, hooks intercept the action and validate it before it executes. Think of them as security guards at every door — they check permissions instantly using small bash scripts, not AI processing.

■
What they are

Bash scripts triggered by Claude Code lifecycle events (session start, before/after tool use, session end). They read a JSON payload from stdin and return exit code 0 (allow) or 2 (block).

✓
What problem they solve

AI models can forget rules mid-session. Hooks enforce constraints deterministically — the phase gate blocks source code writes before the foundation is complete, the quality gate catches build errors, and the data protector blocks destructive commands. No token cost, no forgetting.

Session Init Hooks

Run automatically when a new Claude Code session starts.

ScriptEventWhat It Does
session-startup.sh SessionStart Checks environment (Git, Node, jq), detects terminal type, loads state, and routes to the right workflow.
sync-state.sh SessionStart Reconciles state files on startup — ensures .vibecrew/ JSON is consistent after crashes or manual edits.
error-recovery.sh SessionStart Clears stale lock files and repairs corrupted state from previous interrupted sessions.
compact-reinject.sh SessionStart (compact) Re-injects essential context (active feature, phase, conventions) after Claude Code's /compact clears the context window.

Pre-Action Guards

Intercept actions before they execute. Return exit code 2 to block.

ScriptEventWhat It Does
phase-gate.sh PreToolUse (Write/Edit) Blocks source code writes until the Tier 1 foundation (VISION, TDR, architecture, CLAUDE.md) is complete. Prevents coding before decisions are made.
restrict-paths.sh PreToolUse (Write/Edit) Blocks file writes outside the project root directory. Prevents agents from modifying system files or other projects.
protect-data.sh PreToolUse (Bash) Blocks destructive shell commands: rm -rf, DROP TABLE, DELETE FROM without WHERE, force push, and privilege escalation.
validate-phase-transition.sh PreToolUse (Bash) Enforces phase ordering — ensures foundation steps run in sequence and artifacts are complete before advancing.
validate-signal.sh PreToolUse (Write/Edit) Validates inter-agent signal file schemas, enum values, and feature ID cross-references before they're written.

Post-Action Processors

Run after an action completes successfully.

ScriptEventWhat It Does
format-code.sh PostToolUse (Write/Edit) Auto-formats files after every write using the project's configured formatter (Prettier, ESLint, etc.).
notify.sh Notification / PostToolUseFailure Sends native OS notifications for permission stalls, task completions, and errors. Includes Warp Terminal deep-links when available.

Session End Checks

Run when a session stops to catch issues before they persist.

ScriptEventWhat It Does
quality-gate.sh Stop Runs typecheck, lint, and build on modified source files. Blocks task completion if any check fails — the agent must fix errors before finishing.
claude-md-lint.sh Stop Validates CLAUDE.md file size and structure. Keeps it under the recommended line limit to avoid context bloat.
cost-guardrails.sh Stop Tracks session and daily API costs against configured thresholds. Warns or blocks when spending exceeds limits.
check-context.sh Stop Monitors context window usage and warns at 60% and 80%. Helps prevent sessions from running out of context mid-task.

Hook events mapped to their enforcement scripts

Slash Commands

Slash commands are the primary user interface to VibeCrew. You type a command starting with / and the system handles the rest. Each command is defined as a SKILL.md file with YAML frontmatter (name, description, arguments) and a markdown body containing the full workflow: preconditions, steps, error handling, and agent handoffs.

■
What they are

Commands across several categories: setup, planning, development, quality, safety, session management, and gamification. Some are script-only (zero token cost), others orchestrate multiple agents.

✓
What problem they solve

Without slash commands, you'd need to manually prompt the AI with detailed instructions for every workflow step. Commands encode expert workflows into one-word triggers — /wrap runs quality checks, scores your session, generates docs, and commits, all automatically.

Setup & Onboarding

Run these once when starting a new project or joining an existing one.

CommandWhat It DoesWhen to Use
/setup Verifies dependencies (Git, Node, jq), detects your terminal, and creates the .vibecrew/ folder. First thing you run in any project. Tells you if anything is missing.
/new-project Runs the full 7-step foundation: VISION.md, design system, TDR, architecture diagrams, roadmap, and CLAUDE.md. Starting a brand-new project from scratch. This is the Tier 1 workflow.
/onboard Analyzes an existing codebase — extracts conventions, tech stack, and generates a CLAUDE.md. Adding VibeCrew to a project that already has code.
/profile 8-question interview (or preset selection) that configures how agents communicate and work with you. After setup, to personalize agent behavior for your experience level and preferences.

Planning

Define what to build and track progress.

CommandWhat It DoesWhen to Use
/plan-features Interactive session to define backlog specs: problem statement, acceptance criteria, priority, complexity, dependencies. After foundation is complete, to define what features you want to build.
/idea "text" Captures a one-line idea to backlog.json with status "unplanned". Zero AI cost. Anytime you have a feature idea — quick capture without breaking your flow.
/status Full project dashboard: foundation progress, backlog overview, active feature, recent Vibe Scores. To see where your project stands at a glance. Script-only, no token cost.
/sync-issues Imports open GitHub/GitLab issues by label into the VibeCrew backlog. To pull external issue tracker items into VibeCrew for execution.

Development

Build features and fix bugs.

CommandWhat It DoesWhen to Use
/new-feature "name" Creates a branch, checkpoint, and starts the 6-phase development cycle (Plan → UI Design → Code → Test → Review → Docs). To start building a planned feature. One feature at a time (WIP limit enforced).
/run-backlog Automatically executes features from the backlog by priority. Stops on failure for human review. When you want VibeCrew to work through multiple features autonomously.
/check Runs tests, build, lint, and type-check without modifying any code. Quick health check at any time during development.
/debug Structured debugging with hypothesis testing, variable inspection, and root cause analysis. When something is broken and you need a methodical investigation.
/fix-issue <number> Fetches a GitHub/GitLab issue, diagnoses the problem, implements a fix, tests it, and creates a PR/MR. To fix a specific issue end-to-end from your issue tracker.

Testing & Review

Validate quality, security, and accessibility.

CommandWhat It DoesWhen to Use
/review Code review against feature spec, TDR compliance, and conventions. Findings grouped by severity. After coding is done, before wrapping up a feature.
/tdd Test-driven development cycle: write a failing test first, then implement until it passes. When you want to develop using the red-green-refactor pattern.
/e2e Generates Playwright end-to-end tests with Page Object Model patterns. To add browser-level integration tests for user flows.
/perf-test Generates k6 load, stress, spike, and soak test suites. To benchmark API performance and find bottlenecks under load.
/a11y WCAG 2.1 AA accessibility audit via axe-core. To check your UI for accessibility issues before shipping.

Quality & Analysis

Improve code quality and challenge decisions.

CommandWhat It DoesWhen to Use
/simplify Read-only analysis: finds dead code, over-abstractions, and API surface bloat. You approve each change. When code feels complex or after a big feature to reduce technical debt.
/apply-simplifications Applies the changes you approved from the /simplify analysis. After reviewing /simplify results and selecting what to apply.
/reconsider Devil's advocate analysis of TDR decisions with debate matrices and risk assessments. When you want a second opinion on architectural or technology choices.
/replay Create, list, or apply workflow templates from high-scoring sessions. To reuse a proven workflow pattern from a previous successful session.
/system-review Plugin meta-analysis, cross-project telemetry, and ecosystem research. To analyze VibeCrew's own performance across all your projects.

Safety

Monitor costs, audit security, and fix CI.

CommandWhat It DoesWhen to Use
/audit OWASP Top 10 security scan: injection, auth, XSS, secrets, dependency vulnerabilities. Before shipping to production, or periodically to catch security issues.
/heal Fetches CI logs, diagnoses the failure, and applies a fix (max 3 attempts). When your CI pipeline is failing and you need automated diagnosis.
/cost Real-time cost dashboard: session, daily, weekly, and monthly aggregates with pricing table. To check how much you've spent on AI tokens. Script-only, no token cost.
/undo Lists checkpoints and recent commits, lets you safely revert or reset. When something went wrong and you need to roll back changes.

Session Management

Wrap up work and transfer context between sessions.

CommandWhat It DoesWhen to Use
/wrap Quality gate, Vibe Score calculation, performance coaching, commit, session log, and gamification pipeline. At the end of every session. This is how VibeCrew scores and records your work.
/handoff Generates a structured context transfer document for the next session. When you're stopping mid-feature and need the next session to pick up exactly where you left off.
/release Generates release notes from git history and session logs. When you're ready to publish a new version of your project.
/recover-state Clears lock files and repairs corrupted JSON state. When VibeCrew is stuck or state files are broken after a crash.

Gamification

Track progress, earn rewards, and test your knowledge.

CommandWhat It DoesWhen to Use

Bash Scripts

Scripts are the worker bees of VibeCrew — ~80 small bash programs that do the actual mechanical work. While agents think and make decisions, scripts create files, update project state, calculate scores, and send notifications. They run in milliseconds and always produce the same result for the same input.

■
What they are

Deterministic bash scripts organized by function: core lifecycle, feature management, quality scoring, project analysis, documentation, gamification, and state management. Agents never write state files directly — all mutations go through scripts.

✓
What problem they solve

AI token cost scales with complexity. By offloading mechanical tasks (JSON manipulation, git operations, file formatting) to scripts, VibeCrew keeps AI focused on decisions while scripts handle bookkeeping at zero token cost. Scripts also guarantee consistency — state mutations are atomic and predictable.

Runtime State

Every project using VibeCrew gets a .vibecrew/ folder that stores all runtime state: project configuration, foundation progress, feature backlog, session logs, Vibe Scores, architecture diagrams, and cross-session handoffs. This folder is the system's memory — it persists between sessions and lets agents pick up exactly where the last one left off.

■
What it is

A directory of JSON files and sub-folders created by /setup. Core files: config.json (preferences), state.json (current phase), backlog.json (feature specs), gamification.json (progression). Sub-directories hold sessions, scores, signals, locks, and architecture diagrams.

✓
What problem it solves

AI sessions are stateless — each new conversation starts from scratch. The .vibecrew/ folder gives the system persistent memory: which features are done, what phase you're in, your quality trends, and even architectural diagrams that agents reference instead of re-deriving structure from code.

Core State Files

JSON files that store project configuration and progress.

FileRead ByWhat It Stores
config.json All agents, hooks, status bar Terminal preferences, notification settings, user profile (role, verbosity, autonomy, etc.), cost thresholds, and MCP server toggles.
state.json All agents, hooks, status bar Foundation completion status, active feature name and current phase, feature history, and last session timestamp.
backlog.json Orchestrator, Builder, dashboard Feature specifications with Kanban columns (Ideas → Planned → In Progress → Testing → Review → Done), priority, complexity, and acceptance criteria.
gamification.json Performance Coach, dashboard XP, level, earned badges, skill tree progress, active streaks, and challenge completions. Opt-in via /profile.

Runtime Directories

Sub-directories that store session data and inter-agent communication.

DirectoryWhat It StoresWho Uses It
architecture/ 5 Mermaid .mmd files: system topology, ER schema, state flows, API sequences, and component tree. Builder (reads for context), Doc Generator (freshness check), injected once per session.
sessions/ JSON logs for each session: start/end time, features worked on, Vibe Score, token usage, cost. Performance Coach (trend analysis), dashboard (stats/trends tabs).
scores/ Detailed Vibe Score breakdowns: each deduction and bonus with reasons. Performance Coach, dashboard (trends tab), status bar (current score).
signals/ Inter-agent signal files for communication between worktree agents and the main session. Agents (write signals), hooks (validate schema before write).
locks/ Advisory lock files that prevent concurrent modifications to shared state. Scripts (acquire/release), error recovery (clear stale locks).
handoffs/ Structured context transfer documents created by /handoff for cross-session continuity. Session Startup (detects and loads), agents (reads for context).

Permissions & Safety

VibeCrew uses a defense-in-depth model with three layers of protection. Before any agent action reaches your filesystem, it passes through permission rules, hook guards, and quality gates. This means the AI can work productively without asking for permission every 5 seconds, while being physically unable to do anything destructive.

■
What it is

Three concentric safety layers: settings.json (allow and deny rules), PreToolUse hook scripts (phase gate, path restrictions, destructive command blocking), and Stop hook quality gates (typecheck, lint, build, cost limits).

✓
What problem it solves

AI agents can attempt risky actions — force-pushing, deleting files, running as root, or writing code before architecture is decided. VibeCrew blocks these deterministically with bash scripts, not by hoping the model remembers the rules.

Allowed without prompts

  • File operations — Read, Write, Edit, Glob, Grep
  • npm scripts — test, lint, build, format, type-check
  • Git — status, log, diff, add, commit, checkout, branch, worktree, revert, tags
  • GitHub/GitLab CLI — PR create/list/view, pipeline view
  • Shell utilities — jq, cat, ls, wc, sort, head, tail, mkdir, cp, mv
  • Security audits — npm audit, pip audit, cargo audit, govulncheck

Always blocked

  • Privilege escalation — sudo, su, doas, pkexec
  • Force operations — git push --force, git reset --hard, git clean -f
  • Destructive commands — rm -rf /, rm -rf ~, chmod 777
  • System modifications — npm install -g, kill -9, systemctl, crontab
  • Data destruction — DROP TABLE, DELETE FROM without WHERE (hook layer)
  • Path violations — writes outside project root, source code before foundation

Vibe Dashboard

Every VibeCrew project gets a browser-based dashboard scaffolded into its docs/ folder during /setup. It's a VitePress-powered site that reads live data from .vibecrew/ — the same JSON files that power the CLI — and renders it as interactive charts, Kanban boards, and settings editors. No database, no backend, just local JSON files.

■
What it is

A 7-tab VitePress site (Guide, Kanban Board, Session Stats, Trends, Coverage, Achievements, Settings) with VitePress data loaders that read .vibecrew/*.json files and render them as Vue components. Hot-reloads in dev mode when data changes.

✓
What problem it solves

Terminal output is ephemeral — once you scroll past it, the data is gone. The dashboard gives you a persistent, visual interface to browse your backlog, track quality trends over time, review session history, and edit project settings without memorizing CLI commands.

Dashboard Tabs

📚
Guide

Getting-started docs, command reference, and workflow overview. The default landing tab.

📋
Kanban Board

7-column interactive board (Ideas → Done). Add ideas, drag cards between columns, launch Warp sessions. Reads backlog.json.

📈

Total sessions, average Vibe Score, token usage, and estimated costs. Reads sessions/*.json.

📉

Vibe Score trajectory, token breakdown, and agent activity over time. Reads scores/*.json.

✅

Test coverage gauge and feature delivery progress (completed vs. total backlog).

🏆
Achievements

Level, XP, badges, skill radar chart, and streak calendar. Reads gamification.json.

⚙

Browser-based editor for user profile, notifications, cost limits, MCP servers, and gamification toggles. Writes to config.json.

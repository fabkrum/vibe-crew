Development Lifecycle

Core Workflow

VibeCrew organizes every project into a structured two-tier workflow. Tier 1 builds the project foundation (one-time, sequential). Tier 2 iterates features through a 6-phase cycle. This page provides an overview — see the sub-pages for details on advanced features, personalization, and best practices.

Tier 1: Project Foundation

Before any source code can be written, the phase gate enforces six foundation artifacts in sequence:

/new-project → VISION.md → design-system.css → TDR (Technology Decision Record) → roadmap → Architecture Diagrams → CLAUDE.md Phase gate blocks src/ writes until all six artifacts exist

Each artifact builds on the previous one. The vision defines what you’re building, the design system establishes visual language, the TDR locks in technology choices (with optional adversarial review), the roadmap sequences features, the architecture diagrams distill the architecture into compact Mermaid visuals, and the project CLAUDE.md captures conventions for all future sessions.

Bring Your Own Design System: If you already have a design system or style guide, you can import it at Step 2 instead of running the Design Discovery interview. VibeCrew accepts CSS files, Tailwind configs, JSON tokens, URLs, Figma links, or brand PDFs. The imported tokens are mapped to VibeCrew’s template placeholders, producing identical output files so all downstream agents work unchanged.

Run /new-project for a new project, or /onboard if you’re onboarding an existing codebase. The homepage guide walks through either path step by step.

Tier 2: Feature Development Cycle

Each feature passes through 6 phases. The cycle runs for every feature in your backlog:

1. Plan → 2. UI Design → 3. Code → 4. Test → 5. Review → 6. Docs Each phase produces artifacts tracked by the Vibe Score
  • Plan — Problem statement, acceptance criteria, component breakdown, API design
  • UI Design — Component wireframes using design system tokens
  • Code — Component selection from UI pattern reference, shadcn installation, interaction pattern application, keyboard verification, implementation within TDR boundaries (Builder agent, worktree isolation)
  • Test — Unit tests, integration tests, optional E2E and accessibility checks
  • Review — Code review against feature spec, TDR compliance, and conventions
  • Docs — Feature documentation, CHANGELOG entry, architecture updates if needed
Key commands

/new-feature "name" starts a feature. /check runs quality checks mid-session. /wrap finalizes the session with Vibe Score, commit, and session log. /run-backlog automates the full cycle for each feature with inter-feature context hygiene — forced /compact between features to prevent context degradation across long autonomous runs.

Vibe Score

Every session ends with a score (0–100) calculated from real work artifacts. Starts at 100, applies deductions for prompt churn, tool loops, low cache utilization, missing tests, skipped reviews, and documentation drift. Bonuses for clean sessions, high test coverage, TDD discipline, and complete phase artifacts. The Performance Coach proposes permanent CLAUDE.md rule mutations based on patterns it detects.

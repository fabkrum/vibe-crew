How VibeCrew Works

VibeCrew is a system of interlocking parts: a plugin shell, specialized agents, lifecycle hooks, slash commands, bash scripts, and per-project runtime state. Select a tab to see how each part fits together.

Plugin Structure

VibeCrew is a Claude Code plugin — an add-on that gives Claude Code new abilities. When you open a project with VibeCrew installed, Claude Code reads a manifest file and automatically loads agents, skills, hooks, scripts, MCP servers, and permissions. Everything lives inside the claude-plugin-vibe-crew/ directory.

■
What it is

A self-contained folder with a plugin.json manifest that registers 14 agents, 33 slash commands, 16 hooks, ~80 scripts, and 9 MCP servers.

✓
What problem it solves

Without a plugin, you'd manually configure each agent, permission rule, and automation script for every project. The plugin bundles everything into a single install.

Sub-Agents

Instead of one AI doing everything, VibeCrew splits work across 14 specialized agents — like a real development team with planners, builders, testers, and reviewers. Each agent runs a specific model (Opus for complex decisions, Haiku for fast mechanical tasks, Sonnet for documentation) and operates either inline or in an isolated worktree.

■
What they are

AI "specialists" with scoped tool access, model selection, and turn budgets. The Workflow Orchestrator routes work; the Builder writes code; the Verifier runs tests; the Performance Coach scores sessions.

✓
What problem they solve

A single AI context window fills up fast when researching, coding, and testing in one session. Worktree agents offload expensive research into isolated contexts — only the distilled output enters your main session, saving thousands of tokens.

Agent topology: how agents hand off work to each other

Hooks

Hooks are automatic safety checks that run behind the scenes at zero token cost. When an agent tries to write a file or run a command, hooks intercept the action and validate it before it executes. Think of them as security guards at every door — they check permissions instantly using small bash scripts, not AI processing.

■
What they are

Bash scripts triggered by Claude Code lifecycle events (session start, before/after tool use, session end). They read a JSON payload from stdin and return exit code 0 (allow) or 2 (block).

✓
What problem they solve

AI models can forget rules mid-session. Hooks enforce constraints deterministically — the phase gate blocks source code writes before the foundation is complete, the quality gate catches build errors, and the data protector blocks destructive commands. No token cost, no forgetting.

Slash Commands

Slash commands are the primary user interface to VibeCrew. You type a command starting with / and the system handles the rest. Each command is defined as a SKILL.md file with YAML frontmatter (name, description, arguments) and a markdown body containing the full workflow: preconditions, steps, error handling, and agent handoffs.

■
What they are

33 commands across 7 categories: setup, planning, development, quality, safety, session management, and gamification. Some are script-only (zero token cost), others orchestrate multiple agents.

✓
What problem they solve

Without slash commands, you'd need to manually prompt the AI with detailed instructions for every workflow step. Commands encode expert workflows into one-word triggers — /wrap runs quality checks, scores your session, generates docs, and commits, all automatically.

Bash Scripts

Scripts are the worker bees of VibeCrew — ~80 small bash programs that do the actual mechanical work. While agents think and make decisions, scripts create files, update project state, calculate scores, and send notifications. They run in milliseconds and always produce the same result for the same input.

■
What they are

Deterministic bash scripts organized by function: core lifecycle, feature management, quality scoring, project analysis, documentation, gamification, and state management. Agents never write state files directly — all mutations go through scripts.

✓
What problem they solve

AI token cost scales with complexity. By offloading mechanical tasks (JSON manipulation, git operations, file formatting) to scripts, VibeCrew keeps AI focused on decisions while scripts handle bookkeeping at zero token cost. Scripts also guarantee consistency — state mutations are atomic and predictable.

Runtime State

Every project using VibeCrew gets a .vibecrew/ folder that stores all runtime state: project configuration, foundation progress, feature backlog, session logs, Vibe Scores, architecture diagrams, and cross-session handoffs. This folder is the system's memory — it persists between sessions and lets agents pick up exactly where the last one left off.

■
What it is

A directory of JSON files and sub-folders created by /setup. Core files: config.json (preferences), state.json (current phase), backlog.json (feature specs), gamification.json (progression). Sub-directories hold sessions, scores, signals, locks, and architecture diagrams.

✓
What problem it solves

AI sessions are stateless — each new conversation starts from scratch. The .vibecrew/ folder gives the system persistent memory: which features are done, what phase you're in, your quality trends, and even architectural diagrams that agents reference instead of re-deriving structure from code.

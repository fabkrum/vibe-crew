Release Notes

All notable changes to VibeCrew, following Keep a Changelog and Semantic Versioning.

v1.1.0 v1.0.0
v1.1.0 2026-03-05 Latest

Competitive improvements informed by cross-framework analysis of Superpowers, GSD, BMAD, Ruflo, Ralph Loop, Kiro, Spec Kit, Composio, and Claude Squad.

Session 1 — Agent Prompts, Templates & Scripts

A1: Centralized Agent Helpers

  • New agents/helpers.md with named anchors for shared procedures (register, deregister, profile, state, budget, escalation)
  • All agents reference helpers instead of duplicating instructions — 70-85% token savings on repeated patterns

A2: Pre-Execution Plan Verification Loop

  • Builder validates plans against 4 criteria before execution: goal coverage, dependency integrity, context budget, EARS compliance
  • Max 3 iterations to fix gaps, then proceeds with warnings

A3: TDD Rationalization Resistance

  • Structured resistance tables in TDD prompts that counter common excuses for skipping tests
  • Integrated into Builder and Verifier agent prompts

A4: EARS-Format Acceptance Criteria

  • Plan template uses Easy Approach to Requirements Syntax for testable acceptance criteria
  • Five patterns: Ubiquitous, Event-driven, State-driven, Unwanted, Optional

A5: Status-Driven “What Next?”

  • /status now suggests the most appropriate next action based on current project state

Session 2 — Workflow & Safety Enhancements

B1: Discuss Phase with Decision Taxonomy

  • New Discuss phase between Plan and Code with three decision categories: Locked, Deferred, and Discretion
  • Locked decisions must be followed exactly; Deferred get TODO(deferred) comments; Discretion choices are documented with rationale

B2: PostToolUse Context Monitoring

  • Debounced context monitoring hook fires every 5th tool use with warnings at 45%, 60%, and 80% thresholds
  • Complements the existing Stop hook for continuous protection against context exhaustion

B3: Pause & Resume with Worktree Cleanup

  • /pause commits WIP, creates handoff, stores paused state; /resume restores from preserved branch
  • Clean worktree lifecycle management prevents orphaned branches

B4: Pre-Execution Test Coverage Mapping

  • Nyquist-pattern mapping of existing test coverage to acceptance criteria before code is written
  • Generates Wave 0 test scaffolding tasks for uncovered criteria

Session 3 — Agent Intelligence & Parallel Execution

C1: Per-Agent Persistent Memory

  • JSONL-based memory in .vibecrew/memory/<agent>/<domain>.jsonl with TTL-based auto-pruning
  • Agents accumulate patterns, preferences, and lessons across sessions without bloating CLAUDE.md
  • Enforces 50-entry and 100KB limits per domain with duplicate detection

C2: Agent Overlay Customization

  • Per-project agent overrides in .vibecrew/agent-overrides/<agent>.md survive plugin updates
  • Section-matching merge: matching headings replace, new headings append, frontmatter preserved

C3: Intent-Based Skill Triggering

  • Natural language pattern matching maps user intent to all slash commands
  • Session Startup agent detects intent from conversation and suggests the right skill

C4: Parallel Backlog Execution

  • /run-backlog --parallel analyzes feature dependencies and groups independent features into waves
  • Features within a wave execute simultaneously in separate Agent contexts and worktrees
  • Topological sort respects depends_on relationships; circular dependencies handled gracefully
v1.0.0 2026-03-05 GitHub Release

The first stable release of VibeCrew — a Claude Code plugin that transforms Claude Code into an autonomous vibe-coding operating system.

Highlights

Two-Tier Workflow

  • Tier 1 (Project Foundation) — Sequential process creating VISION.md, design system, TDR, architecture diagrams, roadmap, and CLAUDE.md before any source code can be written
  • Tier 2 (Feature Development) — Iterative 6-phase cycle (Plan → UI Design → Code → Test → Review → Docs) for each feature
  • Phase gate hook enforces planning before coding — no source code writes until foundation is complete

Specialized AI Agents

  • Opus agents for planning, research, code, security, and analysis — tasks where mistakes are expensive
  • Haiku agents for fast, mechanical tasks like routing and running shell commands
  • Sonnet agent for template-driven documentation output
  • Worktree isolation for heavy research, review, and evaluation — keeps your main session fast

Lifecycle Hooks

  • Zero-token bash scripts enforce safety, quality gates, phase ordering, and path restrictions
  • Quality gate runs typecheck, lint, and build on every task completion
  • Context usage warnings at 45% and 60% to prevent slowdowns
  • Cost guardrails with session and daily tracking against thresholds
  • Auto-formatting of written files via PostToolUse hook

Slash Commands

  • Setup & onboarding — /setup, /new-project, /onboard, /profile
  • Planning — /plan-features, /idea, /status, /sync-issues
  • Development — /new-feature, /run-backlog, /check, /debug, /fix-issue
  • Testing & review — /review, /tdd, /e2e, /perf-test, /a11y
  • Quality & analysis — /simplify, /apply-simplifications, /reconsider, /replay, /system-review
  • Safety — /audit, /heal, /cost, /undo
  • Session management — /wrap, /handoff, /release, /recover-state
  • Gamification — /achievements, /quiz
  • Utilities — /quick, /install-skill

MCP Servers

  • Bundled servers for library docs (Context7), browser testing (Playwright, Chrome DevTools), and more
  • Registry of additional servers auto-discovered and injected based on TDR technology choices
  • Conditional activation — Semgrep, Sentry, Supabase, Stripe, Vercel, and Figma enabled from TDR

Planning Workflow

  • Implementation plan files — Builder writes docs/features/{name}/plan.md with structured tasks (Files/Action/Verify/Done) before coding
  • Clarify sub-step — Resolves spec ambiguities before Design phase, checking 6 categories of gray areas
  • ASCII wireframes — Visual layout mockups generated during Design Phase for cheap iteration before code
  • Complexity classification — Features classified as trivial/standard/complex; trivial skips Design and Review, complex enables milestone decomposition
  • Milestone waves — Complex features broken into milestones with dependency analysis and parallel execution of independent milestones
  • Plan staleness detection — Checks if codebase changed since plan was written; auto-refreshes affected tasks
  • Plan revision tracking — Counter in state.json warns after 2+ spec changes mid-feature
  • /quick command — Rapid single-feature execution for small tasks, skipping full backlog workflow

Companion Skills

  • Curated registry — 6 pre-vetted skills from Anthropic, Vercel, Supabase, Cloudflare, and Stripe matched against TDR technology choices
  • Two-tier discovery — Registry match for known skills, then skills.sh search for unmatched technologies (Anthropic → vendor → community priority)
  • 5-gate quality check — Trusted author, repo health, SKILL.md scan, dangerous pattern detection, and script audit before recommending discovered skills
  • /install-skill command — Manual installation from GitHub repos, local paths, or company-internal repositories
  • Builder adaptation — When Anthropic's frontend-design skill is detected, Builder defers aesthetic choices to the skill

Agent Observability

  • Agent identity system — register-agent.sh / deregister-agent.sh for lifecycle tracking with PID, session, and timestamp
  • JSONL event logging — Structured log entries for agent registration, phase completion, errors, and performance metrics
  • Session metrics — Duration, token usage, cost, cache hit rates, and tool call counts per agent session
  • Self-improvement pipeline — Performance Coach analyzes observability data to propose CLAUDE.md rule mutations

Expertise System

  • Structured expertise records — Persist conventions, decisions, and failure patterns across sessions
  • Drift detection — Tracks when codebase conventions diverge from recorded expertise
  • Erosion tracking — Monitors degradation of code quality patterns over time
  • Expertise priming — Agents load relevant expertise records before each phase via expertise-prime.sh

Testing Infrastructure

  • BATS test suite — Comprehensive unit and integration test suites with CI/CD on GitHub Actions
  • Regression test generator — Auto-generates test cases from bug fixes to prevent regressions
  • Test helpers — Isolated temp projects, state fixture builders, command mocking, and hook input constructors

Codebase Onboarding

  • Persistent analysis — /onboard produces 4 analysis docs (conventions, stack, architecture, patterns) that persist across sessions
  • Analysis injection — Builder loads analysis docs before planning to skip re-discovering project conventions

Personalization

  • Multi-dimension user profiles: code literacy, autonomy, PR review style, verbosity, gamification preference, learning mode, and risk tolerance
  • Every agent reads the profile and adapts behavior to your experience level and preferences
  • Preset selection or guided interview via /profile

Gamification & Vibe Score

  • Vibe Score quality rating per session (0–130) measuring prompt efficiency, test coverage, documentation freshness, and workflow compliance
  • XP, leveling, badges, skill trees, streaks, and challenges that reward good development habits
  • Performance Coach proposes permanent CLAUDE.md rule mutations based on anti-pattern detection

Status Line

  • Persistent terminal status bar showing model, context usage, cost, active feature and phase, Vibe Score, and compaction count
  • Updates after every assistant message at zero token cost
  • Graceful degradation when dependencies are missing

Vibe Dashboard

  • Browser-based VitePress dashboard with Kanban board, score trends, achievements, and settings
  • Architecture overview rendering Mermaid diagrams from .vibecrew/architecture/*.mmd
  • Live session data via atomic JSON writes from the status line script

Design Discovery

  • 3-phase interview: Product & Audience Context → Visual Direction → Component Preferences
  • Bring-your-own design system: import from CSS, Tailwind, JSON tokens, URL, Figma, or brand PDF
  • Both paths produce identical output: design-system.css + design-brief.md

Safety & Security

  • Permission rules with allowed and denied tool patterns
  • Dangerous command protection (rm -rf, DROP TABLE, force push)
  • Path restriction to project root
  • OWASP Top 10 security auditing via /audit
  • CI failure diagnosis and repair via /heal (max 3 attempts)

Cross-Session State

  • .vibecrew/ directory with JSON state files, session logs, scores, signals, locks, and handoffs
  • Cross-session context transfer via /handoff
  • Cross-project telemetry with anonymized performance data for /system-review

Documentation

  • Companion docs site built with Astro, self-hosted fonts, dark/light theme, and Pagefind search
  • Setup guides, workflow walkthroughs, architecture reference, glossary, and FAQ
  • Auto-generated docs via Doc Generator agent during /wrap

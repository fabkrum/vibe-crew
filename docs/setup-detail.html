Setup in Detail

This page is the deep-dive companion to the quick-start guide on the homepage. It explains what every setup step does, what gets created, what each script validates, and what the configuration options mean.

Prerequisites

VibeCrew needs a few tools on your machine before it can run. The install.sh script auto-detects your OS and package manager (Homebrew on macOS, apt/dnf/yum on Linux) and offers to install anything missing.

Required

Setup will not proceed without these.

ToolMinimum VersionPurpose
Git2.30+Version control, branch management, worktree isolation for sub-agents.
Node.js18+Runs MCP servers, dashboard dev server, and build tooling.
jq1.6+JSON parsing in all hook and automation scripts. Used hundreds of times across ~80 scripts.

Optional

Missing optional tools trigger warnings, never blockers.

ToolPurposeWhat Happens Without It
GitHub CLI (gh)Create repos, open PRs/issues, sync labels.Git setup falls back to local-only. PRs created manually.
GitLab CLI (glab)Same as GitHub CLI for GitLab-hosted projects.Same fallback to local-only.
terminal-notifierNative macOS desktop notifications with sound.Falls back to terminal bell. No desktop alerts.
Auto-install

Run bash install.sh --yes to skip confirmation prompts and install everything in one shot. The script consolidates multiple brew install commands into a single call.

Bootstrap Script

The one-liner bootstrap command does three things:

  1. Installs Homebrew (macOS only, if missing) — the package manager used to install Git, Node.js, jq, and optional tools.
  2. Clones the VibeCrew repository to your machine.
  3. Runs install.sh --yes to install all dependencies non-interactively. 
One-liner bootstrapcurl -fsSL https://raw.githubusercontent.com/anthropics/vibe-crew/main/bootstrap.sh | bash

If you prefer to inspect the code before running it, use the manual alternative:

Manual installgit clone https://github.com/anthropics/vibe-crew.git
cd vibe-crew/claude-plugin-vibe-crew
bash install.sh
No sudo required

The install script uses Homebrew (macOS) or user-level package managers. It never runs sudo unless your Linux package manager requires it (apt/dnf).

Launching Claude Code

Once installed, you launch Claude Code with the --plugin-dir flag pointing to the plugin folder. This tells Claude Code to read the plugin.json manifest and load all agents, skills, hooks, scripts, MCP servers, and permissions.

Launch with pluginclaude --plugin-dir /path/to/claude-plugin-vibe-crew
📂

New Project

Create an empty directory, cd into it, and launch with --plugin-dir. The Session Startup agent detects there's no .vibecrew/ folder and prompts you to run /setup.

📁

Existing Project

cd into your project and launch with --plugin-dir. If .vibecrew/ exists, Session Startup loads your state and shows a status summary. If not, it prompts for /setup.

The /setup Wizard

Running /setup walks through 11 sequential steps. Each step has clear pass/fail conditions — required steps block progress, optional steps warn and continue.

1

Check Prerequisites

Runs check-deps.sh which outputs a JSON report of every dependency's status, version, and whether it's required or optional.

check-deps.sh output{
  "dependencies": [
    { "name": "Git",  "status": "ok", "found": "2.43.0", "required": "2.30.0", "level": "required" },
    { "name": "Node", "status": "ok", "found": "20.11.0", "required": "18.0.0", "level": "required" },
    { "name": "jq",   "status": "ok", "found": "1.7.1", "required": "1.6",   "level": "required" }
  ],
  "summary": { "passed": 3, "required_failed": 0, "optional_missing": 1, "ready": true }
}

If required dependencies are missing, you're offered two choices: Install now (runs the install commands automatically) or Show commands (prints what to run manually). Optional dependencies generate warnings but never block.

If GitHub CLI (gh) is installed, the script also checks gh auth status to verify authentication.

2

Detect Terminal

Checks environment variables (WARP_SESSION_ID, TERM_PROGRAM) to identify your terminal: Warp, iTerm, VS Code, macOS Terminal, WezTerm, Alacritty, kitty, or tmux. Stores the result in config.json.

If Warp is detected, deep-link notifications are enabled via warp://session/<id> URIs — clicking a notification takes you directly to the correct terminal tab.

3

Test Notifications

Fires notify.sh test to send a test notification via your terminal's best available method (Warp deep-link, iTerm OSC 9, terminal-notifier, or bell fallback). Success confirms the notification pipeline works; failure warns but doesn't block.

4

Check MCP Server Health

Runs check-mcp-health.sh with a 5-second timeout per server. Displays a status table of all 9 bundled MCP servers. Three are enabled by default: Context7, Chrome DevTools, and Playwright. The remaining 6 (Semgrep, Sentry, Supabase, Stripe, Vercel, Figma) are conditionally enabled later based on your TDR technology choices.

Server failures are warnings, not blockers. The system works fine with reduced MCP capabilities.

5

Configure Claude Command

Asks which Claude Code command you use: claude, claude-p, claude-w, or a custom path. This is stored in config.json and used for Warp launch configurations and multi-tab orchestration.

6

Initialize State Directory

Runs init-vibecrew-state.sh which creates the .vibecrew/ directory with all state files and sub-directories. If the directory already exists, you're asked whether to reinitialize. See What Gets Created for the full breakdown.

7

Git Repository Setup

Detects your current git state and offers the appropriate path:

  • Existing remote detected — auto-detects the provider (GitHub/GitLab) from the remote URL and stores it.
  • No remote — asks your preference: GitHub, GitLab, or local-only. For GitHub/GitLab, asks visibility (public/private) and repo name, then creates the remote via CLI.
  • CLI missing or auth failed — gracefully falls back to local-only git.

Updates config.json with the git provider and state.json with git.initialized: true.

8

Verify Initialization

Reads .vibecrew/config.json and validates that required fields exist: terminal, notifications.enabled, created_at, and git_provider. Reports any malformed JSON or missing files.

9

Print Summary

Displays a complete summary: dependency versions, terminal type, Claude command, notification status, MCP server health (N healthy / M total), git provider, state directory status, and Warp launch config. If optional tools are missing, shows install hints.

10

Launch Dashboard

Runs ensure-dashboard.sh which checks if the Vibe Dashboard is already running, relaunches it if the process died, or starts it fresh. Reports the dashboard URL. Silent exit if no docs site exists yet.

11

Prompt for Profile

Checks whether user_profile.interview_completed is true in config.json. If not, prints a reminder to run /profile to personalize the experience. If the profile already exists, this step is silently skipped.

What Gets Created

Step 6 creates the .vibecrew/ directory — the project's runtime state. Here's what's inside.

.vibecrew/ ├── config.json # Terminal prefs, notifications, MCP, cost limits, user profile ├── state.json # Foundation progress, active feature, current phase ├── backlog.json # Feature backlog with Kanban columns and WIP limits ├── gamification.json # XP, level, badges, streaks, challenges (opt-in) ├── architecture/ # 5 Mermaid .mmd diagrams (generated during Tier 1) ├── sessions/ # Session logs: timing, features, scores, cost ├── scores/ # Detailed Vibe Score breakdowns per session ├── signals/ # Inter-agent signal files for coordination ├── locks/ # Advisory locks for concurrent access safety ├── releases/ # Release notes data (JSON) ├── handoffs/ # Cross-session handoff documents ├── workflows/ # Reusable workflow templates (/replay) └── .backup/ # Backup copies of state files

Initial config.json

Created with sensible defaults. Everything is editable later via /profile or the dashboard Settings tab.

.vibecrew/config.json{
  "schema_version": "1.6.0",
  "terminal": "warp",
  "claude_command": "claude",
  "notifications": {
    "enabled": true,
    "sound": "Submarine",
    "on_permission_prompt": true,
    "on_task_complete": true,
    "on_failure": true
  },
  "mcp_servers": {
    "context7": true,
    "chrome_devtools": true,
    "playwright": true
  },
  "cost_limits": {
    "session_warn": 2,
    "session_max": 5,
    "daily_warn": 20
  },
  "user_profile": {
    "interview_completed": false
  }
}

.gitignore Entries

The init script automatically adds entries to your project's .gitignore to keep transient runtime data out of version control while preserving shareable state:

IgnoredTracked
sessions/, signals/, locks/, scores/, .backup/, config.json, gamification.json state.json, backlog.json, architecture/, handoffs/, releases/, workflows/

Warp Launch Config

If Warp terminal is detected, a launch configuration is created at ~/.warp/launch_configurations/<project-name>.yaml with pre-configured tabs and panes for your Claude command.

Telemetry Registration

The project is registered in the central plugin's project-registry.json with an anonymous alias (project-001, project-002, etc.). This powers the /system-review command's cross-project analytics. No project names or paths are stored in telemetry data.

The /profile Interview

After setup, VibeCrew prompts you to run /profile — a 7-question interview (~2 minutes) that personalizes how every agent communicates and behaves. It's completely optional; all agents use sensible defaults without it.

DimensionWhat It ControlsOptions
Code LiteracyHow technical the system's language is in reviews, errors, and docs.Fluent, Conversational, Basic, None
AutonomyHow much VibeCrew does before asking for approval.Full Auto, Checkpoints, Collaborative, Supervised
PR ReviewHow code changes are packaged and merged.Auto-merge, Summary, Review, Walkthrough
VerbosityHow much detail you get in messages and summaries.Minimal, Standard, Detailed, Educational
GamificationHow much of the progression system is visible.All In, Light Touch, Score Only, Disabled
Learning StyleHow the system helps you understand your codebase.Don't Explain, Reference Docs, Inline, Teach Me
Risk ToleranceHow adventurous technology choices are during research.Conservative, Balanced, Progressive, Experimental

See the User Profiles page for full details on each dimension, how agents adapt, and how to change your profile later.

Session Startup

Every time you open a new Claude Code session, the session-startup.sh hook runs automatically. It performs environment validation in the background and outputs a compact 3-line status summary.

What It Checks

CheckAction on Failure
Required tools (git, jq, node)Warns but never blocks session start.
Optional tools (gh)Warns, continues silently.
.vibecrew/ existsPrompts to run /setup.
State file validationRuns state migration if needed.
MCP server healthBounded by 15-second timeout. Never blocks.
Dashboard livenessRelaunches if process died. Silent if no docs site.
Handoff filesDetects and displays handoff from previous session.

Status Output

Always under 200 words. Three lines max.

LineContent
1Foundation status, active feature + phase, or completion status.
2Backlog summary: total features, ready count, done count — or next steps.
3Gamification line (level, streak, challenge) — only if enabled in profile.
Always non-blocking

Session startup always exits with code 0. Every check has timeouts and graceful fallbacks. A broken MCP server or missing optional tool will never prevent you from starting work.

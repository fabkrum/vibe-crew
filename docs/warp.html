Overview

Why Warp for VibeCrew

VibeCrew works with any terminal. But Warp unlocks capabilities that directly improve multi-session AI development: structured output blocks for reviewing agent work, launch configurations for instant workspace setup, Warp Drive for sharing workflows across your team, and session restoration so you never lose your layout.

■

Blocks

Every command is a discrete, navigable, copyable block. When Claude Code produces 200 lines of output, you can scroll within that block without losing your place in the session.

■

Launch Configurations

Save your multi-project workspace as a YAML file. One click and every project opens with Planning, Development, and Terminal panes ready to go.

■

Warp Drive

Share VibeCrew workflows, environment variables, and runbook notebooks across your team. Everyone gets the same tooling, instantly synced.

■

Session Restoration

Quit Warp, restart your Mac, open Warp — your tabs, panes, and recent blocks are restored exactly as you left them.

This page is the single reference for everything Warp + VibeCrew — from installation through advanced features.

Getting Started

Quick Install

  1. Download Warp

    Install from warp.dev. Available on macOS, Linux, and Windows.

  2. Install the Claude Code notification plugin

    Warp has an official Claude Code integration plugin that provides native notifications when a session completes or needs permission. Run these commands inside a Claude Code session (not directly in Warp):

    claude code/plugin marketplace add warpdotdev/claude-code-warp
    claude code/plugin install warp@claude-code-warp

    After running both commands, restart Claude Code for notifications to activate.

  3. Install terminal-notifier

    Required for VibeCrew's notify.sh hook script to send macOS banner notifications.

    bashbrew install terminal-notifier

  4. Send a test notification

    terminal-notifier won't appear in System Settings until it has sent at least one notification. Send a test to register it:

    bashterminal-notifier -message "VibeCrew test" -title "Test Notification"

  5. Enable notifications

    Now open System Settings → Notifications → terminal-notifier (it appears after the first notification) and set alert style to Banners or Alerts. Also enable notifications in Warp Settings → Features → Desktop Notifications.

Notifications

Deep-Linking & Notifications

The killer feature of Warp for VibeCrew: when a notification fires, clicking it takes you to the exact tab that needs attention — no hunting through multiple sessions.

Terminal comparison

TerminalNotification MethodTab Deep-Link
WarpOSC 777 + macOS bannerYes — click goes to exact tab
iTerm2OSC 9 + macOS bannerNo
VS Code TerminalmacOS bannerNo
Terminal.appmacOS bannerNo

How it works

Warp exposes a WARP_SESSION_ID environment variable for each terminal tab. VibeCrew captures this value and constructs a warp://session/<id> URI. When the notify.sh script fires a notification, it passes this URI to terminal-notifier's -execute flag. Clicking the macOS banner executes the deep link, which brings Warp to the foreground and switches to the exact tab.

Agent blocks on permission ↓ notify.sh reads JSON from stdin, extracts notification_type ↓ Captures $WARP_SESSION_ID from environment ↓ Constructs deep link: warp://session/$SESSION_ID ↓ Dispatches via terminal-notifier -execute "open '$DEEP_LINK'" ↓ You click the notification → Warp focuses the exact tab

Verify your session ID

In any Warp tab, run:

bashecho $WARP_SESSION_ID

This should return a UUID. If it's empty, update Warp to the latest version.

Using a different terminal?

VibeCrew works with any terminal. You'll get macOS banner notifications regardless. The only difference is that non-Warp terminals can't deep-link to a specific tab — clicking the notification brings the terminal app to focus but you'll need to find the tab manually.

Window Layout

The Ideal Window Layout

Warp Launch Configurations let you save a complete terminal layout — windows, tabs, panes, working directories, and startup commands — as a YAML file. Open it with one click and your entire VibeCrew workspace is ready.

One launch config per project, three panes each

VibeCrew creates one launch config per project. Each config opens a single tab with three split panes so you can plan, build, and run servers without switching context. Launch only the projects you need — no wasted resources.

  • Left pane (large) — Planning. Runs Claude Code for /plan-features, /idea, /status, /check, and other utility commands. This is your primary focus pane.
  • Right top pane — Development. Runs Claude Code for the active feature (/new-feature, phase work, /wrap).
  • Right bottom pane — Terminal. A raw shell for dev servers (npm run dev), git commands, file browsing, or manual tests. No Claude Code here.

Automatic setup

When you run /setup inside Warp, VibeCrew automatically generates a launch configuration for your project. This works for both new projects (/new-project) and existing ones (/onboard) since both start with /setup.

During setup, VibeCrew asks which Claude Code command to use for this project. This is useful when you have multiple Claude Code profiles — for example, a personal config and a work config:

CommandUse Case
claudeDefault — no profile flag
claude-pPersonal/private profile
claude-wWork profile
customAny alias or wrapper script you use

The chosen command is stored in .vibecrew/config.json as claude_command and used in the generated launch config. You can change it later from the Vibe Dashboard (Settings → Terminal → Claude Command) or by editing the config file directly.

The generated launch config file is saved to:

file location~/.warp/launch_configurations/<project-name>.yaml

For example, a project in ~/projects/my-app creates ~/.warp/launch_configurations/my-app.yaml. The project name is derived from the directory name.

To launch it, open Warp's Command Palette (CMD+P), type "Launch Configuration", and select your project by name. The three-pane layout opens with Claude Code already running in the Planning and Development panes.

Detection & idempotency

VibeCrew only generates the launch config when it detects Warp (via the $WARP_SESSION_ID environment variable). If a config already exists for the project, it is preserved — your customizations are never overwritten. Running /setup again is always safe.

Customizing your layout

The generated config is a standard Warp YAML file that you can edit freely. All launch configs live in a single directory:

bashopen ~/.warp/launch_configurations/

Here's the default structure that VibeCrew generates. The exec value matches whatever Claude command you chose during setup:

~/.warp/launch_configurations/my-app.yaml---
name: my-app
windows:
  - tabs:
      - title: my-app
        color: blue
        layout:
          split_direction: horizontal
          panes:
            - cwd: /Users/you/projects/my-app
              commands:
                - exec: claude-w
              is_focused: true
            - split_direction: vertical
              panes:
                - cwd: /Users/you/projects/my-app
                  commands:
                    - exec: claude-w
                - cwd: /Users/you/projects/my-app

Common customizations:

  • Change the Claude command — replace the exec: value (e.g. claude, claude-p, claude-w) to switch profiles
  • Change the tab color — set color to red, green, yellow, blue, magenta, or cyan (must be lowercase)
  • Add a startup command — add - exec: npm run dev to the bottom-right pane's commands list to auto-start your dev server
  • Remove a Claude pane — delete the commands block from any pane to keep it as a raw terminal
  • Change the split direction — swap vertical and horizontal to rearrange pane positions
Changing the Claude command later

If you need to switch profiles after setup, you have three options: edit the exec: lines in the YAML file directly, update claude_command in .vibecrew/config.json, or change it in the Vibe Dashboard under Settings → Terminal. Note that changing the config only affects future launch config generation — to update an existing launch config, edit the YAML file.

Color-code your projects

Assign a unique color to each project so you can identify them at a glance when multiple tabs are open. When a notification fires, the tab color tells you which project needs attention.

Pane navigation

Use Opt+CMD+Arrow to move between panes by direction. Press Shift+CMD+Enter to temporarily maximize a pane for focused reading, then press it again to restore the layout.

Open configs as tabs, not windows

By default, launching a configuration opens a new window. To open it as a tab in your current window instead, use CMD+Enter when selecting the config from the Command Palette or the + menu. This keeps all your projects in one window for easier tab switching.

Saving your current layout

Rearranged your panes and want to save the result? Open the Command Palette (CMD+P), search for "Save New Launch Configuration", give it a name, and Warp captures your current tabs, panes, and directories. This overwrites the auto-generated YAML with your actual layout.

Output Management

Working with Blocks

Warp's block model is exceptionally useful for AI-assisted development. Every command and its output are grouped into a discrete block that you can navigate, search, copy, filter, and share independently.

Why blocks matter for VibeCrew

When Claude Code implements a feature, it produces dozens of commands with hundreds of lines of output. In a traditional terminal, this is one endless scroll. In Warp, each command is a navigable block.

■

Sticky command headers

Scrolling through long output? The command that produced it stays pinned at the top. You always know which operation you're looking at.

■

Failed command highlighting

Commands that exit non-zero get a red sidebar. When you return to a tab after a notification, failed blocks are immediately visible — no scanning required.

■

Block sharing

Right-click any block → Share. Generates a web permalink with formatting preserved. Perfect for pasting test failures or Vibe Score results into Slack or PRs.

■

Block filtering

Opt+Shift+F on a block reduces output to matching lines only. Use it to filter test output to just failures, or grep CI logs for the error line.

Block workflow for reviewing agent output

When you switch to a tab where Claude Code has been working:

  1. CMD+Up repeatedly to jump through the blocks it produced
  2. Red sidebar? That block failed — investigate
  3. CMD+B to bookmark anything you want to revisit (test results, the /wrap Vibe Score)
  4. Later, Opt+Up/Down to jump directly between your bookmarks
Team Collaboration

Warp Drive for Teams

Warp Drive is a cloud-synced knowledge base built into the terminal. It stores four types of objects: Workflows, Notebooks, Prompts, and Environment Variables. For VibeCrew teams, it's the best way to standardize tooling.

Shared VibeCrew workflows

Warp Workflows are parameterized command templates. Create one for common VibeCrew operations and share it with your team via a Team Workspace.

Example: Start a feature

Create this as a Warp Workflow (via Command Palette → "Create a New Personal Workflow"):

warp workflowName:    VibeCrew: Start Feature
Command: cd {{project_path}} && claude-p '/new-feature "{{feature_name}}"'

Arguments use {{double_curly_braces}} syntax. When you run the workflow via CMD+P, Warp prompts you to fill in each argument. Press Shift+Tab to cycle between them.

Example workflows worth creating

Workflow NameCommandPurpose
VibeCrew: Start Feature cd {{project}} && claude-p '/new-feature "{{name}}"' Start a feature session with one command
VibeCrew: Quick Status cd {{project}} && claude-p '/status' Check project state without entering interactive mode
VibeCrew: Heal CI cd {{project}} && claude-p '/heal' Fix CI failures in one shot
VibeCrew: Run Backlog cd {{project}} && claude-p '/run-backlog' Fire-and-forget batch execution

Dynamic enum arguments

Warp Workflows support dynamic enums — argument values generated by a shell command at runtime. Use this for a feature-name argument that pulls from your actual backlog:

dynamic enumArgument: feature_name
Type:     Dynamic Enum
Command:  jq -r '.features[].id' .vibecrew/backlog.json

Now when you run the workflow, Warp shows a dropdown of your actual backlog features instead of a free-text field. No typos, no guessing.

Sharing with your team

Move a workflow from your Personal Workspace to the Team Workspace in Warp Drive. It syncs in real-time to all team members. Everyone gets the same standardized VibeCrew commands.

Documentation

Notebooks as Runbooks

Warp Notebooks combine Markdown text with executable command blocks. They're the perfect format for VibeCrew onboarding guides and operational runbooks that your team can execute step-by-step, directly in the terminal.

Create a team onboarding notebook

Open Warp Drive, click + → New Notebook. Mix documentation with executable commands:

notebook example### VibeCrew Setup for New Team Members

Welcome! Follow these steps to set up VibeCrew on your machine.

**Step 1: Install dependencies**
> brew install terminal-notifier jq gh

**Step 2: Clone the project**
> git clone {{repo_url}}
> cd {{project_name}}

**Step 3: Run VibeCrew setup**
> claude
Then type:
> /setup

**Step 4: Verify notifications**
The setup wizard sends a test notification. Click it to confirm deep-linking works.

Command blocks (the > lines) have an insert button — click it or press CMD+Enter to execute the command in your active terminal session. Parameters use the same {{curly_brace}} syntax as Workflows.

Useful notebooks to create

■

New developer onboarding

Dependencies, plugin install, Warp config, first /setup run, notification test. Executable from top to bottom.

■

Release checklist

/status check, /audit security scan, test run, changelog review, git tag, deploy command. Each step executable in-place.

■

Incident response

Check CI status, pull logs, run /heal, verify fix, notify team. A runbook that's executable under pressure.

Notebooks sync across the team via Warp Drive and export as Markdown (.md) for version control.

Configuration

Environment Variables

Warp Drive can manage environment variables and inject them into terminal sessions on demand. This is useful for switching between project environments or sharing non-secret configuration across the team.

Per-project variable sets

Create a Warp Drive variable set for each project or environment:

warp drive variable set: "TripFlow Dev"PROJECT_ROOT=/Users/you/projects/tripflow
SUPABASE_URL=https://abc123.supabase.co
NEXT_PUBLIC_APP_URL=http://localhost:3000

Load it into your session from Warp Drive or the Command Palette. Variables persist for the session duration.

Secret management

Warp supports dynamic variables that retrieve secrets from external managers at runtime — Warp stores the retrieval command, never the actual secret.

■

1Password CLI

Warp integrates with op CLI. Select secrets from your vault without leaving the terminal. The secret is injected for the session only.

■

Custom commands

Point to any secret manager: AWS Secrets Manager, HashiCorp Vault, or a custom script. Warp executes the command and injects the result.

Don't store secrets as static variables

Warp Drive static variables are not designed for sensitive data. Use dynamic variables with 1Password or your team's secret manager for API keys, database credentials, and tokens.

AI Integration

Warp AI + Claude Code

Warp has its own AI features (Agent Mode, Warp Pair, Warp Dispatch). These are complementary to Claude Code, not conflicting. They're separate systems with different strengths.

CapabilityWarp AIClaude Code + VibeCrew
Quick command help Warp Agent Mode explains errors, suggests fixes for failed commands Not its purpose — VibeCrew is for full feature development
Feature development Warp Dispatch can run autonomously but lacks VibeCrew's architecture enforcement Full lifecycle: foundation, TDR, 6-phase cycle, Vibe Score, self-improving rules
Multi-model support Claude, GPT, Gemini Claude only (Opus, Sonnet, Haiku selected per agent role)
Context sharing Separate context from Claude Code Persistent via CLAUDE.md, handoffs, session logs

When to use which

■

Use Warp AI for

Quick one-off questions: "What does this error mean?", "How do I undo the last 3 git commits?", "Convert this curl to fetch". Terminal-native problems that don't need project context.

■

Use Claude Code + VibeCrew for

Everything involving your project: feature development, architecture decisions, code reviews, testing, CI healing. VibeCrew provides the structure, scoring, and learning system that Warp AI doesn't have.

They don't conflict

Warp AI and Claude Code run in separate contexts and don't interfere with each other. You can ask Warp's agent a quick question in the same tab where Claude Code is running. The two never see each other's context.

Comfort

Themes for Long Sessions

VibeCrew sessions can run for hours. A good theme reduces eye strain and makes block boundaries, errors, and highlights easier to scan.

Recommended settings

  • Theme: Warp Dark (default) or Dracula are good baselines. Avoid pure-black backgrounds — #0a0a0b to #1a1a2e range is easier on the eyes
  • Font size: 14–15px for comfortable reading at arm's length. Warp Settings → Appearance → Font Size
  • Sync with OS: Enable in Settings → Appearance to auto-switch between light and dark themes based on macOS appearance
  • Input position: "Bottom" (default) keeps the command line at the bottom. Some developers prefer "Top" so output scrolls downward — try both

Custom themes

Create a YAML file in ~/.warp/themes/. Warp also has a Theme Creator that generates a matching color palette from any background image.

accent: '#a78bfa'
background: '#0a0a0b'
foreground: '#fafafa'
details: darker
terminal_colors:
  normal:
    black: '#27272a'
    red: '#f87171'
    green: '#4ade80'
    yellow: '#fbbf24'
    blue: '#60a5fa'
    magenta: '#a78bfa'
    cyan: '#67e8f9'
    white: '#fafafa'
  bright:
    black: '#71717a'
    red: '#fca5a5'

This theme matches the VibeCrew documentation color palette. The accent color is the same purple used throughout the docs and status bar.

Reliability

Session Restoration

Warp saves your window layout, tabs, panes, and recent blocks to a local database on every quit. When you reopen Warp, everything is restored exactly as you left it.

What gets restored

  • Window positions and sizes
  • All tabs with their titles and colors
  • Pane layouts within each tab
  • Working directories for each pane
  • Recent blocks (command history and output)

What doesn't get restored

  • Running processes. Claude Code sessions end when Warp quits. You'll need to restart them. This is why /wrap before closing is critical — it saves your progress to .vibecrew/ state files that survive restarts
  • Bookmarks. Block bookmarks are per-session only
The restart workflow

Always /wrap before quitting Warp. When you reopen, your tabs and directories are restored. Start Claude Code in each tab (claude) and the Session Startup agent reads the latest handoff document — it knows exactly where you left off. The combination of Warp session restore + VibeCrew handoffs means you lose zero context across restarts.

Configuration

Session restoration is enabled by default. To toggle: Warp Settings → Features → "Restore windows, tabs, and panes on startup."

Closed a tab by accident? Shift+CMD+T reopens the most recently closed tab within 60 seconds.

Bonus Tip

Voice Input with Wispr Flow

Typing prompts is the slowest part of working with Claude Code. Wispr Flow is an AI-powered voice dictation app for macOS (and Windows/iOS) that lets you speak your prompts directly into Warp — or any text field. It's roughly 4× faster than typing and works inside any app, including your terminal.

Why it works so well with VibeCrew

■

Natural-language prompts

VibeCrew commands like /idea "..." and /new-feature "..." take plain English descriptions. Speaking them is faster and often produces better, more detailed prompts than typing.

■

Multi-tab speed

When you're juggling 3–4 Warp tabs with different Claude sessions, dictating a quick instruction is much faster than typing it out in each tab.

■

Context-aware formatting

Wispr Flow automatically handles capitalization, punctuation, and formatting. Say "add a login page with email and password fields comma Google OAuth comma and a remember me checkbox" and it produces clean, punctuated text.

■

Hands-free review

While Claude builds a feature in one tab, dictate your next instruction in another tab without switching your hands between keyboard and trackpad.

Getting started

  1. Install Wispr Flow from the Mac App Store or from wisprflow.ai. The free tier includes 2,000 words per week.
  2. Grant accessibility permissions when prompted. Wispr Flow needs this to type into active text fields.
  3. Set your hotkey. The default activation key works, but you can customize it in Wispr Flow preferences. A good choice is a key you don't use often so you can toggle dictation quickly.
  4. Start speaking into Warp. Click into a Warp prompt, press your Wispr Flow hotkey, and speak your command naturally. Wispr Flow transcribes it directly into the terminal input.
Pro tip: think out loud

Voice input changes how you interact with Claude. Instead of condensing your thoughts into a terse typed prompt, you can think out loud: "I want to add a settings page where users can update their display name and email. It should validate the email format client-side and show a success toast when saved." The extra detail actually helps Claude produce better results on the first try — and it takes the same 5 seconds to say that it would take to type "add settings page."

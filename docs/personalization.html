How the Profile System Works

Most AI coding tools treat every user the same. A non-technical founder gets the same unexplained terminal output as a senior developer. A learner is overwhelmed by terse error messages. An experienced developer wades through verbose explanations they don't need. VibeCrew's profile system solves this by adapting every agent's behavior to your experience level, working style, and preferences.

■
What it is

A multi-dimension preference system that controls how every agent communicates, how much autonomy the system takes, how technical the language is, and how adventurous technology choices are.

✓
What problem it solves

A founder who can't read code needs walkthrough PRs with plain English. A senior developer wants minimal output and full autonomy. The profile ensures both get exactly the experience they need — without either having to fight the defaults.

⚠
Completely optional

If you skip the profile interview, every agent uses sensible defaults (checkpoints autonomy, standard verbosity, balanced risk). You can run /profile at any time — or change settings directly in the dashboard.

Dimensions

Each dimension controls a different axis of the system's behavior. Together they create a unique experience tailored to your needs.

📖

Code Literacy

How technical the language in reviews, errors, docs, and commit messages is.

Fluent — technical jargon used freely, minimal comments Conversational — brief definitions for domain jargon Basic — plain English comments on exports and complex logic None — every export gets JSDoc, error messages include plain-language explanations
🎮

Autonomy

How much VibeCrew does on its own before asking for approval.

Full Auto — make decisions and keep going, only stop when blocked Checkpoints — check in at major decisions (tech stack, design, merge) Collaborative — explain each step, user understands and approves Supervised — ask before every significant action, full control
📋

PR Review

How code changes are packaged and merged.

Auto-merge — merge after tests pass, skip PRs entirely Summary — PR with a brief 3-line summary Review — detailed PR with quality gate table and test plan Walkthrough — line-by-line explanations of every change
💬

Verbosity

How much detail you get in messages, coaching, and session summaries.

Minimal — just the facts: status, errors, done Standard — brief explanations of what happened and what's next Detailed — decisions, trade-offs, and alternatives explained Educational — teaches concepts and patterns as you go
🏆

Gamification

How much of the progression system (XP, badges, streaks) is visible.

All In — show everything: XP, levels, badges, streaks, challenges Light Touch — show level and score, skip badges/streaks Score Only — just the Vibe Score, nothing else Disabled — no gamification output at all
🎓

Learning Style

How the system helps you understand your project's codebase.

Don't Explain — just build, user reads the code themselves Reference Docs — generate documentation to read later Inline — comments in code, explanations in commits Teach Me — explain concepts interactively, full understanding
⚖

Risk Tolerance

How adventurous technology choices are during TDR research.

Conservative — proven, battle-tested technologies (3+ years, major backing) Balanced — modern but established, no bleeding-edge or legacy Progressive — newer technologies if they offer clear advantages Experimental — latest and greatest, accepts the risk

The Profile Interview

Running /profile starts an interactive interview — 7 quick questions that take about 2 minutes. The interview is conversational: you can answer with a number (1–4) or describe what you want in plain text.

Interview Flow

StepQuestionSmart Behavior
1How comfortable are you reading code?Calibrates how technical the system's language will be.
2How much should VibeCrew do on its own?Controls approval gates across the entire workflow.
3How should code changes be merged?Determines PR detail level — from auto-merge to line-by-line walkthroughs.
4How much detail do you want in messages?Affects every agent's output length and explanation depth.
5Do you enjoy gamification?Automatically syncs the gamification config (XP display, streak reminders, badges).
6How do you want to learn about your codebase?Controls documentation depth and whether code gets explanatory comments.
7What's your approach to technology choices?Steers the Stack Scout toward stable or cutting-edge technologies.
Re-run anytime
If you already have a profile, /profile shows your current settings first and asks which dimensions you want to change. You don't have to redo the whole interview.

Storage & Scripts

Your profile is stored as JSON in .vibecrew/config.json under the user_profile key. Two bash scripts handle all reads and writes.

.vibecrew/config.json{
  "user_profile": {
    "interview_completed": true,
    "code_literacy": "basic",
    "autonomy": "collaborative",
    "pr_review": "walkthrough",
    "verbosity": "detailed",
    "gamification_preference": "light",
    "learning": "teach",
    "risk_tolerance": "balanced",
    "updated_at": "2026-03-04T14:32:15Z"
  }
}

Profile Scripts

ScriptPurposeKey Behavior
read-profile.sh Universal profile reader called by all agents Merges stored profile over defaults so missing fields are always filled. Always exits 0 — returns defaults if no profile exists. Single bash call, ~500 tokens.
save-profile.sh Writes profile and syncs gamification config Atomic writes via PID-suffixed temp files. Validates config.json exists. Sets interview_completed: true and updated_at timestamp. Uses advisory locks for concurrent safety.

Changing Your Profile

Your profile isn't locked in. As your experience grows and your needs change, you have two ways to update it.

CLI: /profile

Run /profile in any session. If you already have a profile, it shows your current settings and asks which dimensions you want to change. The conversational interview makes it easy to adjust one or all dimensions without starting from scratch.

Dashboard: Settings Tab

Open your project's Vibe Dashboard and navigate to the Settings tab. The browser-based editor lets you modify any profile dimension with dropdowns, see the effect immediately, and save. Changes write directly to .vibecrew/config.json.

Both methods write to the same config.json file. Changes take effect immediately — the next agent that runs will read your updated preferences.

Evolve over time
A learner who started with educational verbosity and collaborative autonomy might switch to standard and checkpoints after a few projects. A founder who initially needed walkthrough PRs might move to summary PRs once they're comfortable with the process. Revisit your profile whenever your workflow feels too noisy or too quiet.

Example: A Founder's Journey

StageProfile ChangesWhy
Week 1 Autonomy: supervised, Verbosity: educational, PR: walkthrough Learning how everything works. Wants full explanations and control.
Month 1 Autonomy: collaborative, Verbosity: detailed, PR: review Understands the workflow. Still wants to approve decisions but doesn't need hand-holding.
Month 3 Autonomy: checkpoints, Verbosity: standard, PR: summary Trusts the system. Only pauses at major decisions. Reads summaries instead of walkthroughs.

Agent Overlay Customization

Beyond profiles, you can customize individual agent behavior per-project by creating override files in .vibecrew/agent-overrides/<agent>.md. Overrides survive plugin updates because they live in your project directory, not the plugin.

AspectHow It Works
Section replacementOverride sections with matching ## Heading names replace the base section entirely
Section appendNew headings in the override are appended after all base sections
Frontmatter preservedModel, tools, isolation, and maxTurns cannot be changed by overrides
Empty/missingNo override file = base agent used unchanged

Example: To make the Builder always use Prisma ORM and CSS Modules for a specific project, create .vibecrew/agent-overrides/builder.md with custom ## Code Phase and ## Project-Specific Conventions sections.

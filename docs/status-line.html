Status Line

While VibeCrew runs, a persistent status line at the bottom of your Claude Code terminal shows real-time session state. It updates after every assistant message at zero token cost — it's powered by a bash script, not the model.

■
What it is

A single ANSI-colored line rendered by statusline.sh. Claude Code pipes session JSON to the script's stdin on every assistant turn, and the script combines that with on-disk state files to produce a compact, color-coded status readout.

✓
What problem it solves

Without the status line, you'd have to run /status repeatedly to check context usage, cost, and active feature. The status line gives you continuous visibility without spending tokens or interrupting your workflow.

Segment Breakdown

Seven segments, left to right:

ModelOpus 4.6The Claude model powering the current session. Parsed from the session JSON that Claude Code pipes to the script on every turn.
Context Bar▓▓▓▓░░░░░░ 38%A 10-character progress bar visualizing context window usage. Each ▓ block represents 10% of the 200k-token window. Color-coded: green at ≤45%, yellow at 46–55%, and red above 55%. This is the most critical indicator — when it turns red, consider running /compact or /handoff to free space before the model starts losing earlier context.
Session Cost$0.42Cumulative API cost in USD for the current session. Helps you track spend in real time rather than waiting for a billing dashboard. The cost guardrail hook fires warnings at configurable thresholds independently, but the status line gives you a continuous readout.
Feature · Phaseauth-flow · CodeThe active feature name (truncated to 16 characters) and its current phase in the Tier 2 cycle: Plan, Design, Code, Test, Review, or Docs. During Tier 1, this shows foundation · Tier-1. If no project is initialized, it displays no project. Read from .vibecrew/state.json on disk.
Vibe Score↑85+The session's quality score (0–150) with a trend suffix: + means the score is improving across sessions, - means declining. Read from the latest score file in .vibecrew/scores/. When no score exists yet, displays ↑--.
Duration12mTotal elapsed session time in minutes. Shows <1m for sessions under 60 seconds. Useful for gauging how long an autonomous run has been going.
Compactions⟳0Number of /compact operations in the current session. Each compaction compresses the conversation to reclaim context window space. A rising number signals a long or context-heavy session. Read from .vibecrew/sessions/.

How It Works Under the Hood

Claude Code supports a statusLine setting in settings.json that points to a bash script. On every assistant turn, Claude Code pipes a JSON object to the script's stdin containing the current model, context window stats, cost, and timing data. The script parses this with jq, reads project state files from .vibecrew/, and outputs a single ANSI-colored line.

Configuration

The plugin's settings.json includes this entry, which Claude Code reads automatically:

settings.json{
  "statusLine": {
    "type": "command",
    "command": "${CLAUDE_PLUGIN_ROOT}/scripts/statusline.sh"
  }
}

stdin JSON Schema

This is the JSON object that Claude Code pipes to statusline.sh on every turn:

stdin payload{
  "model": { "id": "claude-opus-4-6", "display_name": "Opus 4.6" },
  "context_window": {
    "used_percentage": 38,
    "context_window_size": 200000,
    "current_usage": {
      "input_tokens": 1,
      "output_tokens": 9,
      "cache_creation_input_tokens": 653,
      "cache_read_input_tokens": 34682
    }
  },
  "cost": {
    "total_cost_usd": 0.42,
    "total_duration_ms": 720000
  }
}

On-Disk Data Sources

The script combines piped data with on-disk reads:

Data SourceWhat It Provides
stdin JSONModel name, context percentage, session cost, elapsed time
.vibecrew/state.jsonActive feature name and current phase
.vibecrew/scores/score-*.jsonLatest Vibe Score and trend direction
.vibecrew/sessions/session-*.jsonCompaction count for the current session

Graceful Degradation

The status line never breaks your terminal. If jq is missing, it displays just VibeCrew. If .vibecrew/ doesn't exist, project-specific fields show placeholder values (no project, ↑--, ⟳0). The script always exits with code 0, regardless of parse errors.

Dashboard Sidecar

As a side effect, the status line script writes the raw session JSON to .vibecrew/live-session.json using an atomic move operation. The Vibe Dashboard reads this file to display real-time session metrics in the browser without any additional polling or API calls.

Customization

The status line script is fully customizable. You can modify statusline.sh directly to change colors, add segments, or remove fields you don't need. Alternatively, point the statusLine.command setting to your own script — as long as it reads JSON from stdin and outputs a single line to stdout, Claude Code will display it.

Permissions & Safety

VibeCrew uses a defense-in-depth model with three layers of protection. Before any agent action reaches your filesystem, it passes through permission rules, hook guards, and quality gates. This means the AI can work productively without asking for permission every 5 seconds, while being physically unable to do anything destructive.

■
What it is

Three concentric safety layers: settings.json (allow and deny rules), PreToolUse hook scripts (phase gate, path restrictions, destructive command blocking), and Stop hook quality gates (typecheck, lint, build, cost limits).

✓
What problem it solves

AI agents can attempt risky actions — force-pushing, deleting files, running as root, or writing code before architecture is decided. VibeCrew blocks these deterministically with bash scripts, not by hoping the model remembers the rules.

Allowed without prompts

  • File operations — Read, Write, Edit, Glob, Grep
  • npm scripts — test, lint, build, format, type-check
  • Git — status, log, diff, add, commit, checkout, branch, worktree, revert, tags
  • GitHub/GitLab CLI — PR create/list/view, pipeline view
  • Shell utilities — jq, cat, ls, wc, sort, head, tail, mkdir, cp, mv
  • Security audits — npm audit, pip audit, cargo audit, govulncheck

Always blocked

  • Privilege escalation — sudo, su, doas, pkexec
  • Force operations — git push --force, git reset --hard, git clean -f
  • Destructive commands — rm -rf /, rm -rf ~, chmod 777
  • System modifications — npm install -g, kill -9, systemctl, crontab
  • Data destruction — DROP TABLE, DELETE FROM without WHERE (hook layer)
  • Path violations — writes outside project root, source code before foundation

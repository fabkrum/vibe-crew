Getting Started

Quick Install (3 Steps)

VibeCrew ships with an automated bootstrap script that detects your OS, checks all dependencies, and installs only what's missing. Three steps, under two minutes.

  1. Clone VibeCrew

    Clone the repo to a central location. This becomes your single source of truth across all projects.

    bashmkdir -p ~/claude-plugins && cd ~/claude-plugins
git clone https://github.com/fabkrum/vibe-crew.git

  2. Run the bootstrap script

    The installer detects your OS and package manager, checks every dependency, and installs only what's missing. It's idempotent — safe to run multiple times.

    bashcd ~/claude-plugins/vibe-crew/claude-plugin-vibe-crew
./install.sh

    Use ./install.sh --yes to skip the confirmation prompt.

  3. Link to your project and run setup

    Symlink the plugin into your project, start Claude Code with the --plugin-dir flag, and run the setup wizard.

    bashcd ~/projects/my-project
ln -s ~/claude-plugins/vibe-crew/claude-plugin-vibe-crew ./claude-plugin-vibe-crew
claude --plugin-dir ./claude-plugin-vibe-crew
    claude code/setup

    The wizard creates the .vibecrew/ runtime directory, tests notifications, verifies MCP servers, and checks git configuration.

Optional: personalize your experience

Run /profile after setup to adapt VibeCrew to your workflow (verbosity, autonomy level, PR format, gamification, and more). Pick a preset (Builder, Explorer, Founder) or answer 8 questions. Takes about 2 minutes. See User Profile & Personalization for details.

The script supports macOS (Homebrew) and Linux (apt, dnf, yum). Optional dependencies are offered but not required — VibeCrew works without them.

MCP servers

VibeCrew ships with 10 MCP servers. Three are enabled by default: Context7 (documentation lookup), Chrome DevTools (browser debugging), and Playwright (E2E browser testing). All three require no authentication and work immediately.

Six additional servers are auto-enabled when your TDR selects matching technologies: Semgrep, Sentry, Supabase, Stripe, Vercel, and Figma. Authenticated servers require environment variables — the setup wizard shows which ones are needed.

Multi-Project Setup

Most users work on multiple projects. The Quick Install above already sets you up for this — VibeCrew lives in one central location and each project gets a symlink. Here's how it works and how to add more projects.

How it works

Central install (one copy on your machine) ~/claude-plugins/vibe-crew/ # the plugin — shared by all projects Per-project (symlink + local state) ~/projects/tripflow/ claude-plugin-vibe-crew → # symlink to central install .vibecrew/ # project-specific state ~/projects/saas-dashboard/ claude-plugin-vibe-crew → # same symlink, different project .vibecrew/ # its own state ~/projects/mobile-app/ claude-plugin-vibe-crew → # same symlink, different project .vibecrew/ # its own state

The plugin code (agents, hooks, scripts, commands) lives in one place. Each project gets its own .vibecrew/ folder with its own backlog, session logs, scores, and config. Projects are fully isolated from each other.

Adding a new project

Two commands, under 30 seconds:

bashcd ~/projects/another-project
ln -s ~/claude-plugins/vibe-crew/claude-plugin-vibe-crew ./claude-plugin-vibe-crew

Then start Claude Code with the plugin flag and run /setup:

bashclaude --plugin-dir ./claude-plugin-vibe-crew

Updating VibeCrew across all projects

Since every project symlinks to the same central location, updating is one command:

bashcd ~/claude-plugins/vibe-crew && git pull

Every project picks up the changes instantly. No need to copy files, run installers, or touch individual projects. Check the Release Notes after updating to see what changed.

Make it even faster with a shell alias

Add this to your ~/.zshrc to create new VibeCrew projects in one command:

.zshrc# Add to ~/.zshrc
vibecrew-init() {
  ln -s ~/claude-plugins/vibe-crew/claude-plugin-vibe-crew ./claude-plugin-vibe-crew
  echo "VibeCrew linked. Run 'claude --plugin-dir ./claude-plugin-vibe-crew' then '/setup'."
}

vibecrew-update() {
  (cd ~/claude-plugins/vibe-crew && git pull)
  echo "VibeCrew updated to $(cd ~/claude-plugins/vibe-crew && git describe --tags 2>/dev/null || git log -1 --format=%h)"
}

Then for any new project: cd ~/projects/new-project && vibecrew-init

Git and symlinks

By default, Git tracks symlinks as tiny pointer files (not the target contents). This means:

  • Your project repo stays small — only the symlink is committed, not the entire plugin
  • Teammates need their own central install — the symlink points to your local path, so each person clones the plugin to the same location or updates the symlink
For teams: standardize the path

Agree on a team-wide convention like ~/claude-plugins/vibe-crew/. If everyone uses the same path, symlinks work across the entire team with zero config. Document this in your project's README or onboarding guide.

Comparing installation approaches

ApproachBest ForUpdate MethodDuplication
Central clone + symlink Solo devs, small teams git pull once → all projects updated None
Git submodule Teams needing pinned versions git submodule update per project Full copy per project
Direct copy Quick experiments, air-gapped Manual copy per project Full copy per project
Don't mix approaches

Pick one method and stick with it. If some projects use symlinks and others use submodules, updates become confusing and you risk running different VibeCrew versions across projects without realizing it.

What's shared vs. what's project-specific

⇄

Shared (via symlink)

Agent prompts, hook scripts, slash commands, plugin manifest, MCP config, templates. These are the same across all projects and update together.

☗

Project-specific (.vibecrew/)

Backlog, session logs, Vibe Scores, config, state, handoffs, workflows. Each project has its own isolated state folder that's never shared.

✍

Project-specific (project root)

CLAUDE.md, VISION.md, design-system.css, TDR, roadmap. These are created by VibeCrew during the foundation phase and are unique to each project.

⚙

Machine-specific (~/.zshrc)

Shell aliases (vibecrew-init, vibecrew-update), shell traps, Warp Terminal config. Each developer sets these up once on their machine.

Terminal Setup

Warp Terminal

Warp is the recommended terminal for VibeCrew. It provides tab deep-linking (click a notification and land on the exact session that needs attention), structured output blocks, Launch Configurations for instant workspace setup, and session restoration.

Everything you need — installation, deep-linking setup, keyboard shortcuts, Warp Drive, window layouts, and more — is covered on the dedicated Warp page:

Warp Tips & Tricks →

Using a different terminal?

VibeCrew works with any terminal. You'll get macOS banner notifications regardless. The only difference is that non-Warp terminals can't deep-link to a specific tab — clicking the notification brings the terminal app to focus but you'll need to find the tab manually.

Manual Installation

If you prefer to install dependencies yourself instead of using the bootstrap script, here's what you need.

macOS (Homebrew)

bash# Required
brew install jq node

# Optional (PR/MR automation + desktop notifications)
brew install terminal-notifier gh
gh auth login
# Or for GitLab:
brew install glab
glab auth login

Linux (apt)

bash# Required
sudo apt-get install -y git nodejs jq

# Optional
sudo apt-get install -y gh
gh auth login
# Or for GitLab:
sudo apt-get install -y glab
glab auth login

Verify with:

bashgit --version    # 2.30+
node --version   # 18+
jq --version     # 1.6+

Then follow steps 1 and 3 from the Quick Install above (clone and link).

Help

Troubleshooting

/setup says "Unknown skill"

  1. Claude Code does not auto-discover local plugins. You must load the plugin with the --plugin-dir flag: claude --plugin-dir ./claude-plugin-vibe-crew
  2. Verify the symlink target exists: ls -la claude-plugin-vibe-crew/.claude-plugin/plugin.json
  3. Restart Claude Code if you added the flag to an already-running session.

Notifications don't appear

  1. Test terminal-notifier directly: terminal-notifier -message "test"
  2. If nothing appears, reinstall: brew install terminal-notifier
  3. Check macOS: System Settings → Notifications → terminal-notifier → Allow Notifications
  4. Check VibeCrew config: verify .vibecrew/config.json has "notifications": true
  5. Warp deep-links not working: see the deep-linking guide on the Warp page

MCP servers not available

  1. Default servers (Context7, Chrome DevTools, Playwright): These should work out of the box via npx. Try restarting Claude Code.
  2. Bundled conditional servers (Supabase, Stripe, Vercel, Figma, Sentry, etc.): Set the required environment variables, then run bash scripts/enable-mcp-server.sh <name> enable.
  3. Registry servers not yet in .mcp.json (Firebase, Clerk, MongoDB, etc.): Add from the registry with bash scripts/add-mcp-server.sh <key>, or see all available servers with bash scripts/add-mcp-server.sh --list.
  4. All MCP servers are optional. VibeCrew agents gracefully fall back to built-in tools when servers are unavailable.

Stale locks or corrupted state

  1. Run ./scripts/error-recovery.sh to clear lock files and repair corrupted JSON
  2. This resets any in-progress tasks that were interrupted by a crashed session

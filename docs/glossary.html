Glossary

Key terms and concepts used throughout VibeCrew. Click a letter to jump to that section.

ABCDFGHIMOPQRSTVW

A

Agent
A specialized AI prompt that handles a specific role in the development workflow. VibeCrew has 14 agents, each optimized for tasks like planning, coding, testing, or documentation.

B

Backlog
The prioritized list of features to build, stored in `.vibecrew/backlog.json`. Each entry has a name, spec, priority, complexity, and status.
Builder
The Opus-model agent that implements features. Runs in an isolated worktree to keep research tokens out of the main context.

C

CLAUDE.md
The project-level instruction file that Claude Code reads on every session start. Contains conventions, rules, and session learnings. Target: under 200 lines.
Code Auditor
Read-only Opus agent that analyzes existing codebases during `/onboard`, extracting conventions and generating a CLAUDE.md.
Code Reviewer
Read-only Opus agent that reviews code against feature specs, TDR compliance, and coding conventions. Invoked via `/review`.
Code Simplifier
Opus agent that performs read-only analysis of dead code, over-abstractions, and API surface. Invoked via `/simplify`.
Context Window
The total amount of text (tokens) the AI model can process in a single session. VibeCrew targets <50% usage and warns at 60%/80%.

D

Design Discovery
A 3-phase contextual interview (Product Context → Visual Direction → Component Preferences) that produces `design-system.css` and `design-brief.md`.
Design System
The `design-system.css` file containing CSS custom properties (tokens) for colors, typography, spacing, and component styles. Created during Tier 1.
Doc Generator
Sonnet-model agent that creates session logs, changelogs, feature docs, and release notes.

F

Feature Cycle
The 6-phase iterative process in Tier 2: Plan → UI Design → Code → Test → Review → Docs.
Foundation
The set of artifacts created during Tier 1: VISION.md, design system, TDR, architecture diagrams, roadmap, and CLAUDE.md.

G

Gamification
Optional progression system with XP, levels, badges, skill trees, streaks, and challenges. Controlled via `/profile`.

H

Handoff
A structured context transfer document generated by `/handoff` for continuing work in a new session.
Hook
A bash script that runs automatically on specific events (session start, file write, task completion). Hooks enforce rules at zero token cost.

I

Inline Agent
An agent that runs within the main Claude Code session context, sharing its token budget.

M

MCP
Model Context Protocol — a standard for connecting AI models to external tools and data sources. VibeCrew ships with 10 MCP servers.
MCP Server
A service that provides tools to Claude Code via the MCP protocol. Examples: Context7 (docs), Playwright (testing), Supabase (database).

O

Opponent Processor
Opus agent that acts as devil's advocate for TDR decisions, producing debate matrices and risk assessments. Invoked via `/reconsider`.

P

Performance Coach
Opus agent that analyzes session patterns, detects anti-patterns, and proposes permanent CLAUDE.md rule mutations.
Phase Gate
A hook that blocks source code writes until the Tier 1 foundation is complete. Prevents coding without architecture.
Profile
User preferences stored in `.vibecrew/config.json` covering 8 dimensions: role, code literacy, autonomy, PR review, verbosity, gamification, learning, and risk tolerance.

Q

Quality Gate
The Stop hook (`quality-gate.sh`) that runs typecheck/lint/build on modified files after every task completion.

R

Roadmap
The initial feature plan created during Tier 1, typically 5-8 features prioritized by user value.

S

Session Learning
A rule that the Performance Coach proposes to add to CLAUDE.md based on patterns detected during a session. Capped at 15 total.
Stack Scout
Read-only Opus research agent that evaluates technology options and produces the TDR. Uses WebSearch, Context7, and Chrome DevTools.

T

TDR
Technology Decision Record — a structured document recording which technologies were chosen and why. Created by Stack Scout during Tier 1.
Tier 1
The sequential, one-time project foundation phase. Creates VISION.md, design system, TDR, architecture diagrams, roadmap, and CLAUDE.md.
Tier 2
The iterative feature development phase. Each feature goes through the 6-phase cycle: Plan → UI Design → Code → Test → Review → Docs.

V

Vibe Dashboard
A browser-based dashboard showing project metrics: feature Kanban, session stats, Vibe Score trends, test coverage, and achievements.
Vibe Score
A per-session quality metric (0-130) tracking prompt efficiency, test coverage, documentation freshness, and workflow discipline.
VISION.md
The project vision document created in Tier 1 Step 1. Captures what the project is, who it serves, and what success looks like.

W

Worktree Agent
An agent that runs in an isolated git worktree with its own context window. Research tokens stay isolated from the main session.
WIP Limit
Work-in-progress limit: maximum 2 features can be in-progress simultaneously. Enforced by `/new-feature`.

Development Lifecycle

Core Workflow

VibeCrew organizes every project into a structured two-tier workflow. Tier 1 builds the project foundation (one-time, sequential). Tier 2 iterates features through a 6-phase cycle. This page provides an overview — see the sub-pages for details on advanced features, personalization, and best practices.

Tier 1: Project Foundation

Before any source code can be written, the phase gate enforces five foundation artifacts in sequence:

/new-project → VISION.md → design-system.css → TDR (Technology Decision Record) → roadmap → CLAUDE.md Phase gate blocks src/ writes until all five artifacts exist

Each artifact builds on the previous one. The vision defines what you’re building, the design system establishes visual language, the TDR locks in technology choices (with optional adversarial review), the roadmap sequences features, and the project CLAUDE.md captures conventions for all future sessions.

See New Project for a detailed walkthrough, or Existing Project if you’re onboarding an existing codebase.

Tier 2: Feature Development Cycle

Each feature passes through 6 phases. The cycle runs for every feature in your backlog:

1. Plan → 2. UI Design → 3. Code → 4. Test → 5. Review → 6. Docs Each phase produces artifacts tracked by the Vibe Score
  • Plan — Feature spec with acceptance criteria, component breakdown, API design
  • UI Design — Component wireframes using design system tokens
  • Code — Implementation within TDR boundaries (Builder agent, worktree isolation)
  • Test — Unit tests, integration tests, optional E2E and accessibility checks
  • Review — Code review against feature spec, TDR compliance, and conventions
  • Docs — Feature documentation, CHANGELOG entry, architecture updates if needed
Key commands

/new-feature "name" starts a feature. /check runs quality checks mid-session. /wrap finalizes the session with Vibe Score, commit, and session log. /run-backlog automates the full cycle for each feature.

Vibe Score

Every session ends with a score (0–100) calculated from real work artifacts. Starts at 100, applies deductions for prompt churn, tool loops, low cache utilization, missing tests, skipped reviews, and documentation drift. Bonuses for clean sessions, high test coverage, TDD discipline, and complete phase artifacts. The Performance Coach proposes permanent CLAUDE.md rule mutations based on patterns it detects.

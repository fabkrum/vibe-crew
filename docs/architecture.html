How VibeCrew Works

VibeCrew is a system of interlocking parts: a plugin shell, specialized agents, lifecycle hooks, slash commands, bash scripts, per-project runtime state, and a live status line that surfaces it all at a glance. Each piece solves a specific problem that emerges when AI builds software autonomously.

Seven Problems VibeCrew Solves

Problem

AI forgets rules mid-session

Large language models don't reliably follow instructions embedded in long contexts. The more code and conversation accumulates, the more likely the model is to ignore project conventions, skip required steps, or write code before the architecture is decided.

How VibeCrew solves this

Phase gate hookA bash script intercepts every file write. If foundation artifacts (VISION.md, TDR, architecture diagrams) aren't complete, the write is blocked before the model even sees the result.
Quality gate hookAfter every task completion, typecheck, lint, and build run automatically. Failures are caught instantly, not deferred to a later review.
Path restriction hookWrites outside the project root are blocked, preventing accidental modifications to system files or other projects.
Zero token costAll enforcement runs as bash scripts in lifecycle hooks. No tokens are spent reminding the model of rules — they're enforced deterministically.
View hook system →
Problem

Context windows fill up fast

Research tasks — reading documentation, evaluating libraries, analyzing codebases — consume thousands of tokens. Once the context window fills, the model loses earlier instructions and code, forcing expensive restarts.

How VibeCrew solves this

Worktree isolationExpensive agents (Stack Scout, Builder, Code Reviewer) run in separate git worktrees with their own context windows. Only their distilled output re-enters the main session.
MCP serversContext7 serves library documentation on demand. Chrome DevTools inspects live pages. No need to paste large blocks of reference material.
Forced compactionDuring /run-backlog, the system forces /compact between features, preventing context rot across long autonomous runs.
Context warningsA Stop hook monitors usage and warns at 60% and 80%, giving you time to wrap up before hitting the limit.
View agent topology →
Problem

No persistent memory across sessions

Each Claude Code session starts with a blank slate. Without external state, the AI can't know which features are done, what phase you're in, what decisions were made, or what quality trends look like over time.

How VibeCrew solves this

.vibecrew/state.jsonTracks foundation completion status, the active feature, and current phase. Every session starts by reading this file to resume exactly where you left off.
Backlog & signalsFeature specs live in backlog.json. Inter-agent signals coordinate handoffs between agents working in parallel.
Session logs & scoresEvery session is logged with its Vibe Score breakdown. The Performance Coach reads score history to detect patterns across multiple sessions.
Handoff documentsWhen context runs low, /handoff generates a structured document capturing all in-progress work, decisions, and next steps for the next session.
View state structure →
Problem

Manual workflows are error-prone

Remembering to run tests, update docs, check accessibility, format code, and write a changelog entry after every feature is tedious. Steps get skipped, especially during long sessions or when working under pressure.

How VibeCrew solves this

Slash commands/wrap runs quality checks, generates docs, updates the changelog, computes the Vibe Score, and commits — in a single trigger.
/run-backlogPlans, builds, tests, reviews, and documents every feature in the backlog sequentially, with automatic compaction between features.
Auto-formatting hookEvery file write triggers Prettier/formatter automatically. Code style is never a manual step.
33 commandsCover the full lifecycle — from /setup and /plan-features through /tdd, /review, /e2e, /a11y, to /release.
View command reference →
Problem

Quality degrades without oversight

AI-generated code tends to accumulate dead code, unnecessary abstractions, and subtle regressions over time. Without continuous feedback, each session makes the codebase slightly worse — and nobody notices until it's a mess.

How VibeCrew solves this

Vibe ScoreA quantitative quality metric computed every session. Starts at 100, applies deductions for prompt churn, tool loops, missing tests, skipped reviews, and documentation drift. Bonuses for TDD, clean sessions, and full coverage.
Performance CoachAnalyzes score trends across sessions. When anti-patterns recur 3+ times, it proposes permanent CLAUDE.md rule mutations — creating a self-improving feedback loop.
Code ReviewerRead-only review against the feature spec, TDR compliance, and project conventions. Catches architectural drift before it ships.
Code SimplifierDetects dead code, flattens unnecessary abstractions, and reduces API surface area. Runs on demand via /simplify.
View feedback loop →
Problem

Architecture decisions are ad-hoc

Without a structured research phase, AI picks whatever framework or pattern it saw most in training data. Technology choices are made implicitly during coding rather than explicitly during planning — leading to inconsistent stacks and regretted decisions.

How VibeCrew solves this

Two-tier workflowTier 1 (foundation) must complete before any source code is written. This includes VISION.md, design system, TDR, and architecture diagrams — enforced by the phase gate hook.
Stack Scout agentA dedicated research agent that evaluates technologies in an isolated worktree, produces a structured Technology Decision Record (TDR), and never writes application code.
Opponent ProcessorA devil's advocate agent that stress-tests TDR decisions with debate matrices and risk assessments before development begins.
Architecture diagramsFive Mermaid diagrams (system topology, schema, state flows, API sequences, component tree) are generated during Tier 1 and referenced by every agent.
View two-tier workflow →
Problem

You have to babysit every session

Without automation, you're glued to the terminal — reading every output, deciding when to intervene, and context-switching constantly. Running multiple projects in parallel is impossible because each session demands your continuous attention.

How VibeCrew solves this

Interrupt-only notificationsThe system stays silent during normal operation and only pings you on three conditions: permission stalls, task completion, and critical failures. No noise, no polling.
Warp deep-linkingNotifications include warp://session/<id> URIs that jump you straight to the terminal tab that needs attention — no hunting through tabs.
Autonomous feature builds/run-backlog processes the entire feature queue autonomously — planning, building, testing, reviewing, and documenting each feature without manual triggers between steps.
Multi-project parallel workCombined with per-project state (.vibecrew/), you can run VibeCrew across several projects simultaneously, responding only when notified.

The Status Line

While VibeCrew runs, a persistent status line at the bottom of your Claude Code terminal shows real-time session state. It updates after every assistant message at zero token cost — it's powered by a bash script, not the model.

Opus 4.6 ▓▓▓▓░░░░░░ 38% | $0.42 | auth-flow · Code | ↑85+ | 12m | ⟳0

Seven segments, left to right:

SegmentExampleWhat It Shows
ModelOpus 4.6The Claude model powering the current session. Parsed from the session JSON that Claude Code pipes to the script on every turn.
Context Bar▓▓▓▓░░░░░░ 38%A 10-character progress bar visualizing context window usage. Each ▓ block represents 10% of the 200k-token window. Color-coded: green at ≤45%, yellow at 46–55%, and red above 55%. This is the most critical indicator — when it turns red, consider running /compact or /handoff to free space before the model starts losing earlier context.
Session Cost$0.42Cumulative API cost in USD for the current session. Helps you track spend in real time rather than waiting for a billing dashboard. The cost guardrail hook fires warnings at configurable thresholds independently, but the status line gives you a continuous readout.
Feature · Phaseauth-flow · CodeThe active feature name (truncated to 16 characters) and its current phase in the Tier 2 cycle: Plan, Design, Code, Test, Review, or Docs. During Tier 1, this shows foundation · Tier-1. If no project is initialized, it displays no project. Read from .vibecrew/state.json on disk.
Vibe Score↑85+The session's quality score (0–150) with a trend suffix: + means the score is improving across sessions, - means declining. Read from the latest score file in .vibecrew/scores/. When no score exists yet, displays ↑--.
Duration12mTotal elapsed session time in minutes. Shows <1m for sessions under 60 seconds. Useful for gauging how long an autonomous run has been going.
Compactions⟳0Number of /compact operations in the current session. Each compaction compresses the conversation to reclaim context window space. A rising number signals a long or context-heavy session. Read from .vibecrew/sessions/.

How It Works Under the Hood

Claude Code supports a statusLine setting in ~/.claude/settings.json that points to a bash script. On every assistant turn, Claude Code pipes a JSON object to the script's stdin containing the current model, context window stats, cost, and timing data. The script parses this with jq, reads project state files from .vibecrew/, and outputs a single ANSI-colored line.

{
  "model": { "id": "claude-opus-4-6", "display_name": "Opus 4.6" },
  "context_window": {
    "used_percentage": 38,
    "context_window_size": 200000,
    "current_usage": {
      "input_tokens": 1,
      "output_tokens": 9,
      "cache_creation_input_tokens": 653,
      "cache_read_input_tokens": 34682
    }
  },
  "cost": {
    "total_cost_usd": 0.42,
    "total_duration_ms": 720000
  }
}

The script combines this piped data with on-disk reads:

Data SourceWhat It Provides
stdin JSONModel name, context percentage, session cost, elapsed time
.vibecrew/state.jsonActive feature name and current phase
.vibecrew/scores/score-*.jsonLatest Vibe Score and trend direction
.vibecrew/sessions/session-*.jsonCompaction count for the current session

Graceful Degradation

The status line never breaks your terminal. If jq is missing, it displays just VibeCrew. If .vibecrew/ doesn't exist, project-specific fields show placeholder values (no project, ↑--, ⟳0). The script always exits with code 0, regardless of parse errors.

Dashboard Sidecar

As a side effect, the status line script writes the raw session JSON to .vibecrew/live-session.json using an atomic move operation. The Vibe Dashboard reads this file to display real-time session metrics in the browser without any additional polling or API calls.

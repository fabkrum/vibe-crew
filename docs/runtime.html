Runtime State

Every project using VibeCrew gets a .vibecrew/ folder that stores all runtime state: project configuration, foundation progress, feature backlog, session logs, Vibe Scores, architecture diagrams, and cross-session handoffs. This folder is the system's memory — it persists between sessions and lets agents pick up exactly where the last one left off.

■
What it is

A directory of JSON files and sub-folders created by /setup. Core files: config.json (preferences), state.json (current phase), backlog.json (feature specs), gamification.json (progression). Sub-directories hold sessions, scores, signals, locks, and architecture diagrams.

✓
What problem it solves

AI sessions are stateless — each new conversation starts from scratch. The .vibecrew/ folder gives the system persistent memory: which features are done, what phase you're in, your quality trends, and even architectural diagrams that agents reference instead of re-deriving structure from code.

Core State Files

JSON files that store project configuration and progress.

FileRead ByWhat It Stores
config.json All agents, hooks, status bar Terminal preferences, notification settings, user profile (role, verbosity, autonomy, etc.), cost thresholds, and MCP server toggles.
state.json All agents, hooks, status bar Foundation completion status, active feature name and current phase, feature history, and last session timestamp.
backlog.json Orchestrator, Builder, dashboard Feature specifications with Kanban columns (Ideas → Planned → In Progress → Testing → Review → Done), priority, complexity, and acceptance criteria.
gamification.json Performance Coach, dashboard XP, level, earned badges, skill tree progress, active streaks, and challenge completions. Opt-in via /profile.

Runtime Directories

Sub-directories that store session data and inter-agent communication.

DirectoryWhat It StoresWho Uses It
architecture/ 5 Mermaid .mmd files: system topology, ER schema, state flows, API sequences, and component tree. Builder (reads for context), Doc Generator (freshness check), injected once per session.
sessions/ JSON logs for each session: start/end time, features worked on, Vibe Score, token usage, cost. Performance Coach (trend analysis), dashboard (stats/trends tabs).
scores/ Detailed Vibe Score breakdowns: each deduction and bonus with reasons. Performance Coach, dashboard (trends tab), status bar (current score).
signals/ Inter-agent signal files for communication between worktree agents and the main session. Agents (write signals), hooks (validate schema before write).
locks/ Advisory lock files that prevent concurrent modifications to shared state. Scripts (acquire/release), error recovery (clear stale locks).
handoffs/ Structured context transfer documents created by /handoff for cross-session continuity. Session Startup (detects and loads), agents (reads for context).
expertise/ Domain-specific JSONL files: conventions.jsonl, patterns.jsonl, failures.jsonl, decisions.jsonl, performance.jsonl. Records are typed (convention, pattern, failure, decision, reference, guide) and tiered (foundational, tactical, observational). Performance Coach (writes records), all agents (reads for context), apply-mutation.sh (generates Session Learnings view from top 15 foundational records).
erosion/ Erosion tracking data: baseline.json (project baseline captured after first feature ships), erosion-TIMESTAMP.json (per-session metric snapshots), trends.json (rolling 20-session summary with file churn tracking and alert detection). Performance Coach (writes snapshots, computes trends), /wrap (triggers snapshot), /system-review (reads trends).

Ephemeral State Files

Per-session files that reset on each new session start.

FileWhat It StoresWho Uses It
drift-tracker.json Ephemeral per-session drift detection state. Tracks tool call classification (progress, exploration, neutral), a calls_since_progress counter, warnings issued, and escalation events. Reset on each new session start. Hooks (classifies tool calls, increments counters), Workflow Orchestrator (reads warnings/escalations to trigger circuit breakers during autonomous runs).

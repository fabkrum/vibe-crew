UI Pattern Guide

Collecting User Input

Form controls and input components for collecting user data — from simple text fields to complex date pickers and file uploads.

Button button

Also called: action, CTA, submit button

A clickable element that triggers an action. Use for primary actions, form submissions, and confirmations.
Docs →
Checkbox checkbox

Also called: tick box, multi-select option

A box you tick to turn an option on or off. Use for multiple selections from a list or boolean toggles.
Docs →
Combobox command + popover

Also called: autocomplete, type-ahead, searchable dropdown

A search box that filters and suggests options as you type. Use for selecting from large lists (10+ items) like countries or tags.
Docs →
Date Picker calendar + popover

Also called: calendar input, date selector

A calendar popup for picking dates. Use for date selection, date ranges, and scheduling.
Docs →
Form form

Also called: input form, data entry

A group of fields the user fills in and submits. The foundation for any structured data collection.
Docs →
Input input

Also called: text field, text box

A text field where users type short text like names, emails, or search queries.
Docs →
Input OTP input-otp

Also called: verification code, PIN input

Separate boxes for entering a verification code. Auto-advances on digit entry and supports paste.
Docs →
Label label

Also called: field label, input label

Text that describes what a form field is for. Every input must have one.
Docs →
Radio Group radio-group

Also called: single select, option picker

A set of options where you pick exactly one. Use for mutually exclusive choices with 2–5 visible options.
Docs →
Select select

Also called: dropdown, picker, select box

A dropdown list for picking one option from 3–10 choices where space is limited.
Docs →
Slider slider

Also called: range slider, range input

A draggable handle for picking a value within a range, like price or volume.
Docs →
Switch switch

Also called: toggle, on/off switch

An on/off toggle that takes effect immediately. Use for settings like dark mode or notifications.
Docs →
Textarea textarea

Also called: text area, message box

A larger text box for writing longer content like descriptions, comments, or messages.
Docs →
Toggle toggle

Also called: toggle button, pressed button

A button that stays pressed or released. Use for formatting tools like bold/italic or view mode switching.
Docs →
Toggle Group toggle-group

Also called: button group, segmented control

A row of buttons where you pick one (or multiple). Use for view switchers or filter groups.
Docs →
File Upload

Also called: file picker, drag and drop

A button or drop zone for uploading files. Always provide a button alternative alongside drag-and-drop.

Displaying Data

Components for presenting information — tables, charts, cards, and loading states that make data scannable and understandable.

Avatar avatar

Also called: profile picture, user icon

A small circular image showing a user's photo or initials.
Docs →
Badge badge

Also called: tag, chip, pill, status indicator

A small colored label showing status or category. Use for status indicators, counts, or tags.
Docs →
Calendar calendar

Also called: month view, date grid

A month grid showing dates. Use for inline date selection or scheduling displays.
Docs →
Card card

Also called: content card, tile, panel

A bordered box containing related information. Use for product displays, content previews, or dashboard widgets.
Docs →
Carousel carousel

Also called: image slider, slideshow, gallery

A sliding gallery showing one item at a time with navigation arrows. Use sparingly.
Docs →
Chart chart

Also called: graph, visualization, data chart

A visual graph showing data trends and comparisons. Always provide a table alternative for accessibility.
Docs →
Data Table table

Also called: sortable table, data grid

A table with sorting, filtering, and pagination. Use for structured data with 5+ columns.
Docs →
Table table

Also called: static table, simple table

A simple table for displaying rows of data. Use for static displays, comparison tables, or pricing.
Docs →
Progress progress

Also called: progress bar, loading bar

A bar showing how far along a task is. Use for file uploads, multi-step processes, or loading.
Docs →
Skeleton skeleton

Also called: placeholder, shimmer, loading skeleton

A placeholder shape that shows where content will appear while loading. Replaces spinners for layout-aware loading.
Docs →

Navigation

Wayfinding components that help users move through your application — menus, tabs, sidebars, and breadcrumbs.

Breadcrumb breadcrumb

Also called: path, trail, page path

A trail showing where you are in the site hierarchy.
Docs →
Command command

Also called: command palette, spotlight, Cmd+K

A keyboard-triggered search box for finding actions and content quickly (Ctrl/Cmd+K).
Docs →
Dropdown Menu dropdown-menu

Also called: action menu, kebab menu, three-dot menu

A menu that appears when you click a button, showing a list of actions.
Docs →
Menubar menubar

Also called: top menu, application menu

A horizontal bar of menus like File, Edit, View — for complex desktop-style applications.
Docs →
Navigation Menu navigation-menu

Also called: nav bar, site nav, mega menu

The main site navigation with links and optional dropdown sections.
Docs →
Pagination pagination

Also called: page numbers, pager

Page numbers for navigating between pages of a long list. Default choice over infinite scroll.
Docs →
Sidebar sidebar

Also called: side nav, navigation drawer, left panel

A navigation panel on the left side of the screen. Use for dashboard apps and admin panels.
Docs →
Tabs tabs

Also called: tab bar, tabbed interface

Tabs along the top that switch between different content sections.
Docs →

Feedback & Status

Status indicators and notifications that keep users informed about what happened, what went wrong, or what to do next.

Alert alert

Also called: banner, notice, warning

A colored banner showing an important inline message — warnings, success, errors, or info.
Docs →
Alert Dialog alert-dialog

Also called: confirmation dialog, are-you-sure

A popup asking you to confirm a significant action before it happens. Use for destructive or irreversible operations.
Docs →
Sonner (Toast) sonner

Also called: toast, snackbar, notification popup

A small popup message that appears briefly and disappears. Use for action confirmations and non-critical errors.
Docs →
Empty State

Also called: zero state, no data, blank state

A friendly message shown when there's no data yet, with a clear next step. Never show a blank page.

Overlays & Modals

Floating layers that appear on top of the page — dialogs, drawers, tooltips, and popovers for focused interactions.

Dialog dialog

Also called: modal, popup, lightbox

A popup window that appears on top of the page with a backdrop. Focus is trapped inside until closed.
Docs →
Drawer drawer

Also called: bottom sheet, slide-out panel

A panel that slides in from the bottom or side. Great for mobile-friendly detail views and filters.
Docs →
Popover popover

Also called: popup, floating panel, bubble

A small floating panel next to a button. Use for rich tooltips, mini-forms, or extra controls.
Docs →
Sheet sheet

Also called: side panel, slide-over, off-canvas

A panel that slides in from the side. Use for settings, detail views, or shopping carts.
Docs →
Tooltip tooltip

Also called: hint, hover tip, info bubble

A small label that appears on hover or focus. Use for icon-only buttons or additional context.
Docs →
Context Menu context-menu

Also called: right-click menu

A menu that appears on right-click. Use for desktop app-like interfaces. Always provide alternative access.
Docs →
Hover Card hover-card

Also called: preview card, link preview

A preview card that appears when you hover over a link. Use for user profiles or entity summaries.
Docs →

Layout

Structural components that organize page content — accordions, resizable panels, scroll areas, and content separators.

Accordion accordion

Also called: collapsible section, expandable, FAQ

Sections that expand and collapse when you click their headings. Use for FAQs or grouped settings.
Docs →
Aspect Ratio aspect-ratio

Also called: responsive container, fixed ratio box

A container that keeps images or videos at the right proportions regardless of screen size.
Docs →
Collapsible collapsible

Also called: disclosure, show/hide, toggle section

A section you can expand or collapse with a single toggle. Use for optional details or advanced options.
Docs →
Resizable resizable

Also called: split pane, draggable divider

A divider between panels you can drag to resize. Use for code editors or comparison views.
Docs →
Scroll Area scroll-area

Also called: scrollable container, custom scrollbar

A container with custom scrollbars for overflowing content like chat windows or code blocks.
Docs →
Separator separator

Also called: divider, horizontal rule

A visual line separating sections of content. Use between content groups or menu sections.

Interaction & Performance Patterns

Performance and UX patterns that make interfaces feel fast and responsive — lazy loading, caching strategies, and optimistic updates.

Optimistic UI

Also called: instant update, optimistic update

Updates the interface instantly when you perform an action. If something goes wrong on the server, it quietly retries or rolls back.
Docs →
Skeleton Loading

Also called: placeholder loading, shimmer

Shows the page shape while content loads, so the layout doesn't jump around when data arrives.
Docs →
Import on Interaction

Also called: lazy load on click, deferred import

Heavy components like date pickers or rich text editors load only when you click on them.
Docs →
Import on Visibility

Also called: lazy load on scroll, below-fold loading

Content below the fold loads as you scroll to it, keeping the initial page load fast.
Docs →
List Virtualization

Also called: virtual scroll, windowed list

Only renders the rows you can see — handles thousands of items smoothly without slowing down.
Docs →
Prefetch on Hover

Also called: link prefetch, predictive loading

Starts loading the next page when you hover a link, so navigation feels instant.
Docs →
Progressive Disclosure

Also called: show more, advanced options

Shows simple view first, details on demand. Keeps interfaces approachable without hiding power.
Docs →
Stale-While-Revalidate

Also called: SWR, background refresh, cache-first

Shows cached data immediately, refreshes in the background. Dashboards and feeds feel instant.
Docs →
Debounced Search

Also called: throttled input, delayed search

Waits until you stop typing before searching. Prevents unnecessary requests while you compose your query.
Infinite Scroll vs Pagination

Also called: load more, endless scroll

Paginated by default (better for SEO and accessibility). Infinite scroll only when explicitly chosen for feed-type content.
Route-Based Splitting

Also called: code splitting, page-level splitting

Each page only loads the code it needs. Automatic in Next.js, Remix, and SvelteKit.
Docs →
Page Transitions

Also called: route animation, view transition

Smooth animations between page navigations. Respects user's reduced-motion preference.
Docs →

Keyboard & Focus Patterns

Accessibility patterns for keyboard and screen reader users — focus management, key bindings, and live announcements.

Focus Trapping

Also called: modal focus, focus lock

Tab stays inside the popup until you close it. Every modal, dialog, drawer, and sheet must trap focus.
Docs →
Focus Restoration

Also called: return focus, focus return

When a popup closes, focus returns to the button that opened it. Maintains keyboard user's place on the page.
Docs →
Arrow Key Navigation

Also called: arrow keys, directional navigation

Arrow keys move between items in a list, menu, or grid. The standard keyboard pattern for grouped elements.
Docs →
Roving Tabindex

Also called: managed focus, single tab stop

Tab enters a group of items, arrow keys move within it, Tab leaves. Prevents excessive tab stops.
Docs →
Skip Link

Also called: skip navigation, skip to content

A hidden link that lets keyboard users jump past navigation to the main content. Must be the first focusable element.
Docs →
Visible Focus Ring

Also called: focus indicator, focus outline

A clear outline shows which element is currently focused. Never remove focus styles without providing a visible replacement.
Docs →
Escape to Close

Also called: dismiss on escape, escape key

Pressing Escape closes any overlay — popovers, dialogs, drawers, dropdowns, and tooltips.
Docs →
Enter/Space to Activate

Also called: keyboard activation

Enter or Space triggers buttons and links. Every clickable element must respond to both keys.
Docs →
Live Regions

Also called: ARIA live, dynamic announcements

Screen readers announce dynamic changes — toast notifications, form errors, loading states — without moving focus.
Docs →

Tips: What Users Say vs What Agents Build

VibeCrew agents translate plain language into precise component vocabulary. Here are common examples:

What you say What gets built
"A dropdown for picking a country"Combobox (type-ahead search with 200+ items)
"A popup to confirm deleting"Alert Dialog (traps focus, requires explicit choice)
"A sidebar with links"Sidebar + Navigation Menu (keyboard navigable, collapsible)
"A table with sorting"Data Table (sortable headers, pagination, filterable)
"A toast message"Sonner (auto-dismissing, accessible live region)
"A settings page"Tabs + Form + Switch (progressive disclosure, instant toggles)
"A like button"Button + Optimistic UI (instant update, silent retry on failure)
"A dashboard"Card grid + Chart + Skeleton Loading + SWR (fast perceived load)
"A search bar"Combobox + Debounced Search (waits until you stop typing)
"A list of 500 items"Data Table + List Virtualization (only renders visible rows)

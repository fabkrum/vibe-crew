Overview

What is the Vibe Dashboard

The Vibe Dashboard is a VitePress-powered documentation site scaffolded into every VibeCrew project during /setup. It lives in your project's docs/ folder and provides a browser-based interface for browsing development metrics, managing your feature backlog, and editing project settings.

The dashboard reads live data from .vibecrew/ — the same JSON files that power the CLI commands. It includes 7 tabs: a getting-started guide, a Kanban board, session statistics, Vibe Score trends, test coverage, achievements, and a settings editor.

Not the companion docs you're reading now

This page documents the per-project Vibe Dashboard that gets scaffolded into your project. It's separate from the VibeCrew companion documentation site (the one you're reading right now).

Getting Started

How to Start It

The dashboard is a standard VitePress site. Start it with three commands from your project root:

bashcd docs
npm install
npm run docs:dev

Then visit http://localhost:5173 in your browser. The dashboard loads instantly and hot-reloads when .vibecrew/ data changes.

Run it alongside your dev server

Open a separate terminal tab for the dashboard. It runs on its own port and doesn't interfere with your application's dev server. In Warp, use a split pane or a dedicated tab.

Features

Dashboard Tabs

The dashboard ships with 7 tabs. Each tab reads from specific .vibecrew/ JSON files via VitePress data loaders.

Guide

The default landing tab. Contains the same getting-started documentation that's scaffolded into docs/system/getting-started.md — a quick reference for setup, commands, and workflow.

Kanban Board

A 7-column visual board showing every feature in your backlog across its workflow stages:

  • Backlog — Ideas captured via /idea or /plan-features
  • Planned — Features with written specs, ready to build
  • UI Design — In the design phase (Stitch or manual)
  • In Progress — Currently being built by the Builder agent
  • Review — Code review in progress
  • Testing — Running tests and quality checks
  • Done — Feature complete, wrapped, and documented

Data source: .vibecrew/backlog.json

Session Statistics

Aggregate metrics across all your development sessions:

  • Total sessions — Number of completed sessions
  • Average Vibe Score — Your mean score across all sessions
  • Total tokens — Input + output token usage
  • Estimated cost — Cumulative API cost

Data source: .vibecrew/sessions/*.json

Trends

Time-series visualizations of your development patterns:

  • Vibe Score line chart — Score trajectory across sessions
  • Token breakdown — Input vs. output tokens per session
  • Agent activity — Which agents ran and how often

Data source: .vibecrew/scores/*.json

Coverage

Quality metrics at a glance:

  • Test coverage gauge — Percentage of code covered by tests
  • Feature delivery progress — Completed features vs. total backlog

Achievements

The gamification system rendered visually:

  • Level & XP — Your current level and experience points
  • Badges — Earned badges with unlock conditions
  • Skill radar — Radar chart of your development skills
  • Streak calendar — Daily activity streak tracking

Data source: .vibecrew/gamification.json

Settings

A browser-based editor for .vibecrew/config.json. You can modify:

  • User profile — Role, code literacy, autonomy, verbosity, and other profile dimensions
  • Notifications — Toggle notification delivery and sound
  • Cost limits — Set per-session and per-feature cost caps
  • MCP servers — Enable or disable optional MCP integrations
  • Agent behavior — Adjust agent-specific settings
  • Gamification — Toggle scoring, achievements, and XP display
Settings save only works in dev mode

When running npm run docs:dev, the Settings tab writes changes directly to .vibecrew/config.json. In a static production build (npm run docs:build), there's no server to handle writes — the Settings tab displays a read-only view with copyable JSON instead.

Architecture

Data Flow

The dashboard reads data through a simple pipeline:

.vibecrew/*.json # Raw data written by VibeCrew agents | VitePress data loaders # .data.ts files that read and transform JSON | Vue components # Render charts, tables, cards, forms | Browser # Hot-reloads when data files change

Data loaders run at build time (for static builds) or on each page load (in dev mode). In dev mode, VitePress watches the .vibecrew/ directory and triggers hot-reloads when any JSON file changes — so running /wrap in a Claude Code session updates the dashboard in real time.

No database required

All data lives in flat JSON files inside .vibecrew/. There's no database, no backend server, and no external dependencies beyond VitePress itself. The dashboard is a pure static site that reads local files.

Deployment

Production Build

To generate a static HTML version of the dashboard:

bashcd docs
npm run docs:build

The output goes to docs/.vitepress/dist/. You can deploy this to any static hosting provider (Vercel, Netlify, GitHub Pages) to share project metrics with your team.

Snapshot your metrics

A production build captures a point-in-time snapshot of your .vibecrew/ data. This is useful for sprint reviews, stakeholder updates, or archiving project history.

Help

Troubleshooting

Dashboard shows empty/no data

The dashboard reads from .vibecrew/ JSON files that are created as you work. If you haven't completed any sessions yet:

  1. Run /new-project to create the project foundation
  2. Build at least one feature with /new-feature "name"
  3. Close the session with /wrap — this writes session data, scores, and updates the backlog

After your first /wrap, all dashboard tabs will populate with data.

Port 5173 is already in use

If another dev server is using port 5173, VitePress will automatically try the next available port (5174, 5175, etc.). Check the terminal output for the actual URL. You can also specify a port explicitly:

bashnpm run docs:dev -- --port 5200

Settings changes don't persist

The Settings tab can only write to .vibecrew/config.json when VitePress is running in dev mode (npm run docs:dev). If you're viewing a static build, Settings shows a read-only view with copyable JSON that you can paste into .vibecrew/config.json manually.

Hot-reload isn't working

  1. Make sure you're running the dev server (npm run docs:dev), not viewing a static build
  2. Check that .vibecrew/ is in the same project root where you started VitePress
  3. Try restarting the dev server — VitePress occasionally needs a restart after major file structure changes

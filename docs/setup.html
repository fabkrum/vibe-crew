Installation from Scratch

A complete walkthrough from zero to a fully operational VibeOS environment.

Step-by-Step Installation

  1. Install system dependencies

    These are needed for notifications, JSON parsing in hooks, and PR automation.

    bashbrew install terminal-notifier jq
brew install gh && gh auth login

  2. Add the plugin to your project

    Copy or symlink the VibeOS plugin directory into your project root. Symlinking is recommended for teams so updates propagate automatically.

    bash# Option A: Direct copy
cp -r /path/to/claude-plugin-vibe-os/ ./claude-plugin-vibe-os/

# Option B: Symlink (recommended for teams)
ln -s /path/to/claude-plugin-vibe-os ./claude-plugin-vibe-os

# Option C: Git submodule (best for version control)
git submodule add <repo-url> claude-plugin-vibe-os

  3. Verify plugin detection

    Start Claude Code in your project directory. It reads the .claude-plugin/plugin.json manifest and loads VibeOS automatically.

    bashcd /path/to/your-project
claude

    You should see the VibeOS session startup agent run on first launch.

  4. Run the setup wizard

    Inside Claude Code, run:

    claude code/setup

    The wizard walks you through terminal selection, notification testing, MCP server verification, git checks, and creates the .vibeos/ runtime directory.

  5. Install MCP servers (optional but recommended)

    Context7 saves ~1,500 tokens per API lookup by fetching documentation on-demand instead of pasting it into chat. Puppeteer enables browser automation for research and visual testing. Both are configured in mcp-servers.json.

  6. Verify the full pipeline

    • Notifications: Tested during setup wizard
    • Session startup: Exit and restart Claude Code — the startup agent should show a 3-line status summary
    • Phase gate: Try writing a source file before running /new-project — it should be blocked

Configuring Warp Terminal

Warp provides the best VibeOS experience thanks to its deep-link support. When a notification fires, you click it and land on the exact tab that needs your attention — no hunting through 15 open sessions.

Why Warp Is Recommended

WarpOSC 777 + macOS bannerYes — click goes to exact tab
iTerm2OSC 9 + macOS bannerNo

How Deep-Linking Works

Warp exposes a WARP_SESSION_ID environment variable for each terminal tab. VibeOS captures this value and constructs a warp://session/<id> URI. When the notify.sh script fires a notification, it passes this URI to terminal-notifier's -execute flag. Clicking the macOS banner executes the deep link, which brings Warp to the foreground and switches to the exact tab.

Agent blocks on permission ↓ notify.sh reads JSON from stdin, extracts notification_type ↓ Captures $WARP_SESSION_ID from environment ↓ Constructs deep link: warp://session/$SESSION_ID ↓ Dispatches via terminal-notifier -execute "open '$DEEP_LINK'" ↓ You click the notification → Warp focuses the exact tab

Setup Steps for Warp

  1. Install Warp

    Download from warp.dev and complete the initial setup. Warp runs on macOS and Linux.

  2. Enable desktop notifications in Warp

    Open Warp Settings → Features → ensure Desktop Notifications is enabled.

  3. Verify WARP_SESSION_ID

    In any Warp tab, run:

    bashecho $WARP_SESSION_ID

    This should return a UUID. If it's empty, update Warp to the latest version.

  4. Allow macOS notifications

    Go to System Settings → Notifications → terminal-notifier and ensure "Allow Notifications" is on. Set the alert style to Banners or Alerts.

  5. Select Warp during /setup

    When the VibeOS setup wizard asks "Which terminal do you use?", select Warp. This is stored in .vibeos/config.json and determines how notifications are dispatched.

  6. Test the full loop

    The setup wizard sends a test notification. Click it — you should be taken back to the exact Warp tab where Claude Code is running.

Using a different terminal?

VibeOS works with any terminal. You'll get macOS banner notifications regardless. The only difference is that non-Warp terminals can't deep-link to a specific tab — clicking the notification brings the terminal app to focus but you'll need to find the tab manually.

Troubleshooting

Notifications don't appear

  1. Test terminal-notifier directly: terminal-notifier -message "test"
  2. If nothing appears, reinstall: brew install terminal-notifier
  3. Check macOS: System Settings → Notifications → terminal-notifier → Allow Notifications
  4. Check VibeOS config: verify .vibeos/config.json has "notifications": true
  5. Warp deep-links not working: run echo $WARP_SESSION_ID — should return a UUID

MCP servers not available

  1. Context7: Verify it's configured in your Claude Code settings. Try a test query
  2. Puppeteer: Ensure the Puppeteer MCP server is running and configured
  3. Both are optional. VibeOS works without them — you just miss the token efficiency benefits

Stale locks or corrupted state

  1. Run ./scripts/error-recovery.sh to clear lock files and repair corrupted JSON
  2. This resets any in-progress tasks that were interrupted by a crashed session

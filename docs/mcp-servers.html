MCP Servers

MCP (Model Context Protocol) servers give agents access to external tools and services — documentation lookup, browser automation, database inspection, payment APIs, and more. VibeCrew ships with bundled servers and a registry of additional ones that get activated on demand once the project's architecture is clear.

■
What they are

Lightweight tool servers that run alongside Claude Code via npx. Each server exposes a set of tools (search docs, run browser, query database) that agents can call during their work. Configured in .mcp.json.

✓
What problem they solve

Without MCP servers, agents would paste entire library docs into the context window (~5,000+ tokens per lookup). Context7 replaces that with a single tool call (~1,500 tokens saved per query). Service-specific servers (Supabase, Stripe) let agents inspect schemas and APIs directly instead of guessing from docs.

On-Demand Integration

VibeCrew doesn't load all MCP servers upfront. Only 3 general-purpose servers are enabled by default. The rest activate after the TDR (Technology Decision Record) is finalized during Tier 1, when VibeCrew knows exactly which technologies the project uses.

▶
How auto-discovery works

After TDR approval, sync-mcp-from-tdr.sh reads the technology decisions, pattern-matches them against the MCP registry, and auto-enables matching servers. If the TDR mentions "Supabase," the Supabase MCP server activates. If it mentions "Stripe," payment tools appear. Servers that need environment variables (API keys) are flagged for setup.

⚠
Why wait for architecture?

Loading unused MCP servers wastes tool-discovery tokens and clutters the agent's tool list. Claude Code's Tool Search dynamically loads only relevant tool definitions when 5+ servers are active — but fewer active servers still means faster routing and lower overhead.

Default Servers (Always Enabled)

These 3 servers are useful for any project regardless of tech stack. They're enabled in .mcp.json from the start.

ServerWhat It DoesUsed By
Context7 Up-to-date documentation lookup for libraries and frameworks. Replaces pasting docs into context (~1,500 tokens saved per query). Stack Scout, Builder, all research tasks
Chrome DevTools Browser automation and inspection via Chrome DevTools Protocol. Navigate pages, inspect elements, capture screenshots. Builder (visual verification), E2E testing
Playwright End-to-end browser testing and automation. Drives real browsers for integration tests. /e2e, Builder (component testing)

Fallback & Health Monitoring

All MCP servers are optional. If a server fails to connect, crashes, or isn't configured, agents gracefully fall back to built-in tools. No MCP server is required for VibeCrew to function.

✓
Graceful degradation

If the Supabase MCP is unavailable, the Builder reads migration files instead of inspecting the live schema. If Context7 is down, agents use WebSearch. Every agent's prompt includes explicit fallback instructions.

⚠
Health probes

check-mcp-health.sh sends a JSON-RPC initialize probe to each enabled server with a 2-second timeout. Failed servers are reported as "degraded" in /status output.

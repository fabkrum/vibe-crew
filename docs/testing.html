Testing Strategy

VibeCrew provides testing commands for your project code and includes its own comprehensive test suite for the plugin's 127 bash scripts. This page covers both.

⚒
Project Testing 4 slash commands for TDD, E2E, accessibility, and performance testing in your project.
⛓
Plugin Test Suite 1413 unit tests + 69 integration tests validating VibeCrew's own scripts.

Testing Your Project

VibeCrew provides 4 testing commands that work on your project code. Each integrates with the Vibe Score — running these commands earns bonuses, skipping them incurs deductions.

CommandToolWhat It Does
/tdd Vitest / Jest Red-green-refactor cycle. Writes ONE failing test, implements minimum code to pass, refactors, and commits. Produces a Discipline Score (0–10) measuring TDD adherence.
/e2e Playwright Scaffolds Page Object Model, generates spec files with accessibility-first locators, and runs with trace-on-failure for debugging.
/a11y axe-core WCAG 2.1 AA audit: automated axe scan, keyboard navigation checklist, ARIA validation. Saves a JSON report to the project.
/perf-test k6 Load, stress, spike, and soak test profiles. Configures thresholds and reports p95/p99 latency, throughput, and error rates.
⚠
Project tests, not plugin tests

These commands test your application code. The section below covers VibeCrew's own internal test suite.

TDD Rationalization Resistance

The /tdd command includes built-in resistance to common reasons for skipping test-driven development. When the agent detects “red flag” phrases (like “I’ll add tests later” or “this is too simple to test”), it stops and returns to the Red phase. The Iron Law: write code before the test? Delete it. Start over.

Plugin Test Suite

VibeCrew's 127 bash scripts form complex workflow chains. 1413 unit tests validate individual scripts in isolation. 69 integration tests validate the chains compose correctly — catching the category of bugs that only appear when script A's output becomes script B's input. All tests run in isolated temp directories with mocked external tools — zero network, zero side effects.

How Tests Are Isolated

Every test creates an ephemeral project directory, runs in isolation, and cleans up after itself.

Mocking Strategy

External tools are always mocked. Internal scripts run for real in integration tests.

LayerWhat's MockedHow
External CLIs gh, glab, node, npm mock_command() — executable stub prepended to PATH
Package managers bun, pnpm, yarn Same PATH prepend pattern
System tools terminal-notifier, timeout Same pattern
File system None — uses real temp dirs mktemp -d with cleanup in teardown
Git Real git in temp repos git init in setup, real commits when needed
Internal scripts Not mocked in integration tests Scripts call each other directly

Running Tests

The test runner supports three modes via a single entry point. 

tests/run-tests.sh              # All tests (unit + integration)
tests/run-tests.sh unit         # Unit tests only
tests/run-tests.sh integration  # Integration tests only

Regression Test Feedback Loop

When bug fixes are committed without accompanying tests, VibeCrew automatically generates regression test skeletons to close the loop.

    B -->|No| C["detect-fix-commits.sh"]
    C --> D["generate-regression-test.sh"]
    D --> E["Skeleton committed
with skip marker"]
    B -->|Yes| F["No action needed"]
    style A fill:#fde8e8,stroke:#333
    style E fill:#e8fde8,stroke:#333

Fix commits without tests trigger automatic skeleton generation during /wrap.

The Vibe Score applies a -5 deduction per fix commit without a regression test. After 3+ sessions with uncovered fixes, the Performance Coach proposes a CLAUDE.md mutation enforcing TDD-style bug fixing.

CI Pipeline

GitHub Actions runs two parallel jobs on push/PR to main.

JobSuiteSpeedTimeout
unit-tests tests/*.bats ~30s Default
integration-tests tests/integration/*.bats ~2-5min 10min

Both run on ubuntu-latest + macos-latest matrix with fail-fast: false.

Frequently Asked Questions

Common questions about VibeCrew, organized by topic. Can't find your answer? Check Tips & Troubleshooting for more detailed guidance.

Getting Started

What is VibeCrew?

VibeCrew is a Claude Code plugin that transforms Claude Code into an autonomous development team. It orchestrates multiple AI agents, enforces architecture-first development, and manages the full software development lifecycle — from project vision to deployment.

Do I need coding experience to use VibeCrew?

No. VibeCrew is designed for users at all skill levels. Run /profile to set your experience level, and VibeCrew adapts its explanations, autonomy, and output style accordingly. Non-technical founders can build production-grade apps using the Founder preset.

What terminals does VibeCrew support?

VibeCrew works with any terminal. Warp Terminal is recommended because it provides tab deep-linking (click a notification to jump to the exact session), structured output blocks, and Launch Configurations. But iTerm2, VS Code Terminal, Terminal.app, and others all work fine.

How do I install VibeCrew on multiple projects?

Clone VibeCrew once to a central location (e.g., ~/claude-plugins/vibe-crew/), then symlink into each project. See the Multi-Project Setup guide.

Workflow

What's the difference between Tier 1 and Tier 2?

Tier 1 is the one-time project foundation: VISION.md, design system, TDR, architecture diagrams, roadmap, and CLAUDE.md. It runs sequentially and must complete before any source code can be written.

Tier 2 is the iterative feature cycle: Plan → UI Design → Code → Test → Review → Docs. Each feature goes through this 6-phase process.

Can I skip the foundation (Tier 1)?

No. The phase gate hook blocks source code writes until the foundation is complete. This is intentional — writing code without architecture decisions leads to rework, inconsistency, and technical debt. The foundation typically takes 15-30 minutes and saves hours of rework later.

How do I add VibeCrew to an existing project?

Use /onboard instead of /new-project. The Code Auditor agent analyzes your codebase, extracts conventions, derives a design system from existing styles, and generates a CLAUDE.md. See Existing Projects.

What does /run-backlog do?

/run-backlog auto-executes features from your backlog by priority. It runs the full Tier 2 cycle for each feature, including code review, and stops on failure for human review. VibeCrew forces a /compact between features to prevent context rot during long autonomous runs.

Cost & Performance

How much does VibeCrew cost to run?

VibeCrew itself is free and open source. The cost comes from Claude API usage. A typical foundation session costs $5-15, and feature sessions cost $2-8 depending on complexity. Use /cost to see real-time spending and /profile to configure cost guardrails.

How does VibeCrew keep token costs down?

Several mechanisms: (1) worktree agents isolate research tokens from the main session, (2) hooks enforce rules at zero token cost, (3) MCP servers like Context7 replace pasting docs (~1,500 tokens saved per query), (4) CLAUDE.md is kept under 200 lines, and (5) forced compaction between features in /run-backlog prevents context rot.

What is the Vibe Score?

A per-session quality metric starting at 100. Points are deducted for prompt churn, tool loops, skipped tests, and documentation drift. Bonuses are awarded for complete artifacts, high cache utilization, TDD discipline, and clean sessions. Range: 0-130. See Vibe Score details.

Troubleshooting

The phase gate is blocking my writes. What do I do?

This means the Tier 1 foundation isn't complete yet. Run /status to see which foundation steps are missing, then run /new-project (or /onboard for existing projects) to complete them. The phase gate only blocks source code writes — config files, documentation, and .vibecrew/ state files are always writable.

My session state is corrupted. How do I fix it?

Run /recover-state to clear lock files and repair corrupted JSON. If that doesn't work, you can manually delete the .vibecrew/locks/ directory. Your backlog, session logs, and scores are never deleted during recovery.

Notifications aren't working.

Check these in order: (1) Test terminal-notifier directly: terminal-notifier -message "test". (2) Check macOS: System Settings → Notifications → terminal-notifier. (3) Verify .vibecrew/config.json has "notifications": true. See the full troubleshooting guide.

An MCP server isn't connecting.

Default servers (Context7, Chrome DevTools, Playwright) work via npx — try restarting Claude Code. For conditional servers (Supabase, Stripe, etc.), ensure the required environment variables are set. Run bash scripts/enable-mcp-server.sh <name> enable to activate. All MCP servers are optional — agents gracefully fall back to built-in tools.
